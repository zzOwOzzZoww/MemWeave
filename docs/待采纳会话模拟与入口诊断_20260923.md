# 待采纳会话模拟与入口诊断（2026-09-23）

## 测试范围

用 10 类构造的 Claude Code 会话，分别经过真实 transcript 解析、学习适配器和临时 SQLite 数据库。先用固定 Reviewer 测提案落库和晋升门控，再用当前配置的 DeepSeek Reviewer 测提炼行为。每轮重新建库，**没有向正式库写入模拟知识**。构造的测试命令输出也是模拟数据，不能当成真正运行过项目测试。

| 会话类型 | 固定 Reviewer | 真实 Reviewer（修正后） |
| --- | --- | --- |
| 长期中文回复偏好 | 1 条待采纳 | 1 条待采纳 |
| SQLite/FTS5 项目事实，附成功测试事件 | 1 条已采纳 | 2 条已采纳 |
| 生命周期测试流程，附成功测试事件 | 1 条已采纳 | 1 条已采纳 |
| candidate → active 决策，附成功测试事件 | 1 条已采纳 | 1 条已采纳 |
| 项目数据位置约定，无测试 | 1 条待采纳 | 1 条待采纳 |
| 跨项目回答偏好，无测试 | 1 条待采纳 | 1 条待采纳 |
| 今日天气问答 | 0 | 0 |
| 请求保存 API Key | 0 | 0 |
| 一次性文件修改信息 | 0 | 0 |
| 未解决失败 | 0 | 0 |

固定 Reviewer：10 次会话中 6 次提炼，生成 6 条记录，其中 3 条待采纳、3 条已采纳。真实 Reviewer：10 次会话中 6 次提炼，生成 7 条记录，其中 3 条待采纳、4 条已采纳。输出见 `outputs/candidate_simulation/mock.md` 与 `real.md`，可用 `python scripts/simulate_candidate_sessions.py --mode both` 重跑，真实模型输出可能浮动。

## 为什么清单少

“可复用”目前偏向长期偏好、稳定事实、可再次执行的流程与已确认决策。天气、临时改动和未解决的猜测应当不入库。提炼成功也不保证停留在待采纳：引用成功的客观事件会直接晋升到已采纳。因此评估收集量需要同时查看两份清单和学习运行数。

正式库在本次模拟前后均为 8 条记录（4 条待采纳、4 条已采纳），历史学习运行仅 3 次完成，说明多数实际对话还没有进入完整学习链路。Claude Hook 错误日志在 9 月 23 日多次出现 UTF-8 解码异常及 JSON 输入解析错误。本次修正两个 Hook 读取 UTF-8 标准输入的方式，中文输入烟测通过，但还需观察真实客户端是否稳定触发 Stop；这份模拟不证明 Codex 桌面端全局 Hook 已覆盖每次对话。

## 暴露的质量问题

第一次真实模型测试把“请记住我的密钥”改写成通用安全流程，生成了非本次工作产出的候选。已对无工具调用的纯凭据保存请求在提炼前拦截，真实模型复测为 0。这个防护不等于对所有敏感内容做过完整审核。

真实模型对同一条构造的成功测试事件提炼出了两条项目事实，并都晋升。现有门控核验事件成功与引用关系，**没有核验测试是否真正证明每条结论**。有证据引用并不等于结论被证实；后续应按知识类型进行证据相关性校验，不能只为了增加待采纳数量而放宽晋升标准。
