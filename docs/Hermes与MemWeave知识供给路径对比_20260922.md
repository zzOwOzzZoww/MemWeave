# Hermes 与 MemWeave：知识供给路径的对比

日期：2026-09-22
起因：*"我看那个 Hermes 也是用 skill md 和记忆完成的自学习啊，我也是这样子做的，只不过换成了公共知识库，问题在哪"*

---

## 一句话回答

**问题不在"记忆机制"，而在你无意中换掉的那个环节：Hermes 把「该给 agent 看哪条知识」交给
agent 自己的语义判断，你把它交给了 BM25 的字面检索。**

Hermes 的学习机制你确实抄对了；**但它根本没有"检索"这一层，所以它的方案里没有可抄的经验。**
你换来的这一层，是全新的一层，也是唯一承重的一层。

---

## 2. Hermes 的两条知识通道，都不是检索

读完 `hermes-agent` 源码后的实况：

| 通道 | 实现 | 候选集 | 谁决定"给 agent 看什么" |
|---|---|---|---|
| **持久记忆**（MEMORY.md / USER.md） | `prompt_builder` 用 `_read_text_with_timeout()` **直接全量读入 system prompt** | 全部（硬上限 2,200 / 1,375 字符） | 不需要决定——**全都给** |
| **技能**（SKILL.md） | 所有技能的 name + description 以快照形式**全量注入**（~3k tokens）；全文由 `skill_view(name)` 按需加载 | 全部技能的**标题+描述** | **agent 自己**（看清全部选项后选一个读） |

Hermes 确实有 FTS5（`hermes_state_fts.py`），但那是 **`session_search` 用的会话历史检索**，
不是知识供给通道。

**关键**：Hermes 的两条通道，一条**全量摊开**，一条**把选择权交给 agent 的语义理解**。
它从来不需要"猜"用户问的是哪一条——因为要么全给了，要么选项清单全在眼前。

---

## 3. 你换掉的到底是什么

| | Hermes | MemWeave（改造前） |
|---|---|---|
| 容量 | 2,200 字符 + 3k tokens 描述预算 | **几乎无限** |
| 候选可见性 | 全部可见（记忆全量 / 技能标题全量） | 只有被检索命中的才可见 |
| 选择机制 | **agent 的语义判断** | **BM25 的字面匹配** |
| 失败模式 | 上下文膨胀 | **静默漏召**——agent 根本不知道有更好的知识存在 |

**你用「检索」换了「容量」。** 这个交换本身没错——公共知识库要无限扩容就必然要检索。
问题在于：**"该看哪条知识"本质是语义任务，你把它降级成了统计任务。**

而漏召是**静默失败**：检索错了，agent 不会报错，它只会拿着错误的知识、或者什么都拿不到，
然后自信地给出答案。Hermes 没有这个失败模式——它的候选集是"全部"，漏不掉。

---

## 4. 三处后果，都有实测数据

| # | 后果 | 实测 |
|---|---|---|
| 1 | **同构语料下 BM25 判别力崩坏** | 20 条同构知识共库后，判别力从 100% 塌到 30%；单独 phrase 查询只命中 1 条证明索引没错、是排序错。修复后 6/20 → 20/20 |
| 2 | **检索排序成了事实上的仲裁者** | 冲突知识暴露率 100%，两条都进上下文，模型唯一依据是呈现顺序 |
| 3 | **证据强度信息没有送到决策者面前** | `confidence` 对验证次数不敏感 + context 不展示 `verified_count` → 证据 3:1 时伤害仍 20%；暴露计数后降到 **0%** |

第 3 条最能说明问题：**修好它不是靠更好的算法，只是把已有的事实（验证了几次）告诉模型。**
Hermes 的全量注入模式天然不会有这个问题——它把一切事实都摆出来了。

---

## 5. 但你有 Hermes 没有的东西

别把这次对比读成"你做错了"。写入端你比 Hermes 严：

| 维度 | Hermes | MemWeave |
|---|---|---|
| 写入默认 | **自由写**（`memory.write_approval=false`，agent 说写就写） | **证据门控**：晋升须引用成功的客观验证事件 |
| 记录状态机 | 记忆无状态；技能有 active/stale/archived | candidate / active / **quarantined** |
| 否定机制 | 无（记忆靠 agent 手工整理） | `rejected` → 自动隔离 |

**实测效果**：
- 未验证的坏知识 **0% 暴露**（`search()` 只返回 active）
- 被否定的坏知识 **0% 暴露**，任务恢复 100%
- 学习链路 **20/20 全 auto 晋升**，无人工兜底

这两条是 Hermes 那套（全量注入 + 无状态记忆）做不到的。**你的记忆比它的更"有纪律"。**

---

## 6. 结论与下一步

**要补的，恰恰是 Hermes 没有的那一层。**

因为 Hermes 不检索，所以"检索判别力"这件事在它的设计里不存在，
**没有任何经验可以抄**——这块只能自己练。而这正好是你可以做出差异化的地方：

1. **检索层判别力**（已做：稀有判别词优先，6/20 → 20/20）
2. **冲突仲裁**（未做：同族同名的正确/错误记录，目前只能靠 BM25 排序）
3. **证据强度的排序权重**（已做一半：暴露给模型有效；但排序层仍是 BM25 优先，`verified_count` 只是二级键）
4. **伪造验证的防御**（未做：若能伪造验证事件，证据强度会反过来变成攻击杠杆）

**给汇报/简历的表述**：

> 现有自学习框架（如 Hermes）采用「记忆全量注入 + 技能描述全量可见」，
> 把选择权交给 agent 的语义判断，因此不需要检索层，容量被锁死在上下文预算内。
> 我的工作是把知识供给扩展到**无限容量**，代价是必须引入检索；
> 我定位并修复了检索层的判别力缺陷，并验证了把证据强度暴露给决策者
> 可将坏记忆造成的任务失败率从 20% 降到 0。
