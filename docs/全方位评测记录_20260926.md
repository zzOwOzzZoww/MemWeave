# MemWeave 全方位评测记录

日期：2026-09-26

本轮评测覆盖 Core、检索、答案充分性、知识准入、生命周期治理、LFHV 恢复、恶意知识、双向 Adapter、产品安装和性能。除明确标注的安装烟测外，评测都使用临时 SQLite，不读取或修改正式知识库。离线评测没有调用模型；另外单独运行了一次 DeepSeek `deepseek-flash` 真实模型对照，结果单列，不与离线指标混合。

## 1. 总结

通过项：

- 完整回归：`393 passed, 9 subtests passed`。
- 答案充分性受控集：可回答命中率 100%，拒答净空率 100%，额外噪声记录为 0。
- 自然表达边界：注入 50/50，知识准入 20/20。
- 120 场景决策矩阵：200 个已执行观察全部通过；其中 40 个需要模型审查的 admission 观察未执行。
- 生命周期 100 条：控制组和治理组任务代理成功率均为 100%，负向注入率为 0%；20 条被归档记录被 LFHV 探针发现并恢复。
- 误杀实验：控制组 100%，显式归档组 0%，策略归档组 0%，恢复组回到 100%；说明 LFHV 可检测并撤销错误归档。
- 错误知识实验：候选状态的错误知识不暴露；已激活的错误知识虽然可能进入上下文，但最终采用率为 5%，拒绝后暴露归零，任务伤害为 0%。
- 双向原生 Hook：Codex 可召回 Claude Code 来源知识，Claude Code 可召回 Codex 来源知识，无关问题为空，MCP 不是必要条件。
- DeepSeek 真实模型 100 条生命周期对照：Baseline 成功率 10%，MemWeave Auto 100%，Oracle 100%；归档 20 条后 Auto 100%，LFHV 恢复 20 条后 Auto 100%。Auto 的 TTFT P50/P95 约 1,040/1,554ms，Baseline 约 1,159/1,721ms。该结果是一次固定数据集、固定模型的受控实验，不能直接外推到生产。
- 产品安装验收：wheel、干净安装、桌面快捷方式、Runtime、UI、原生 Hook、后台学习全部通过。

未通过或需要继续处理的项：

- 小型通用检索集仍暴露 Recall@3 50%、负向注入率 40%。其中英文知识配中文问题的改写查询全部漏召回，说明当前 FTS 不是语义检索；10 个负例中有 4 个返回了旧知识，说明没有结构化主体和答案槽位时仍会走兼容旧策略。
- 120 场景中的 40 个 admission 观察没有调用模型，不能把“200/200”表述为完整三层决策准确率。
- 真实模型生命周期实验只跑了一次固定数据集，治理/LFHV 结果仍不能外推到生产。

## 3. 答案充分性结果

答案门现在区分三种情况：

1. 没有相关候选；
2. 找到了主题相关候选，但缺少主体、关系或对象，不能回答；
3. 找到了覆盖关系和对象的证据，只注入支撑答案的子集。

受控集结果：

| 指标 | 结果 |
| --- | ---: |
| 可回答命中率 | 100%（6/6） |
| 拒答净空率 | 100%（3/3） |
| 可回答问题额外噪声案例率 | 0%（0/6） |
| 可回答问题平均额外记录 | 0 |
| P50/P95 | 约 3.2/10.2ms |

这证明的是门控逻辑在结构化样本上的行为，不是通用语义理解能力。真实会话仍需要主体、关系、对象的标注样本来验证。

## 4. 性能与兼容性

100 条三轮检索阶段基准的结果：

- 旧实现 P50/P95：8.976/14.145ms。
- 新实现冷缓存 P50/P95：9.283/15.662ms。
- 新实现热缓存 P50/P95：7.999/13.356ms。
- 答案充分性阶段自身 P95：约 0.5ms。
- 结果顺序和注入内容与旧实现保持兼容；33 个差异全部是已记录的父标题修复，没有未预期差异。

因此答案门没有明显增加热路径开销，主要性能成本仍在候选生成和 bridge/anchor 扩展。

## 5. 双向通道验收

原生 Hook 烟测最初失败，原因是测试夹具没有注册 Agent。Hook 的 fail-closed 行为是正确的：未加入 MemWeave 的 Agent 不应获得共享知识。补齐 `codex` 和 `claude-code` 的启用注册后，烟测通过：

- Codex 召回 Claude Code 来源知识：通过。
- Claude Code 召回 Codex 来源知识：通过。
- 无关问题不注入：通过。
- 不依赖 MCP：通过。

MCP 互通烟测也通过，但它验证的是可选网关，不代表 Core 依赖 MCP。

## 6. 当前主要短板与下一轮顺序

第一优先级是通用检索的拒答和跨语言问题。现在没有主体元数据的旧知识会保持兼容旧策略，导致天气、历史、来源等无关问题仍可能拿到主题相近的知识。下一轮应增加一个轻量查询意图分类：事实询问、项目检索、澄清/闲聊、外部实时信息，并对实时信息和明显无关问题先做拒答。

第二优先级是英文知识与中文问题的召回。当前 n-gram/FTS 只能证明词面检索，不能宣称语义召回。应增加写入时同义词/中英文别名，或可选的本地 embedding；默认仍保留 FTS，避免强制增加依赖和延迟。

第三优先级是把 `subject_terms`、关系和对象从“可选字段”逐步变成新知识的结构化元数据。旧记录继续兼容，但新记录如果没有证据主体，应降低自动注入等级，进入候选或要求二次复核。

第四优先级是接入真实脱敏会话，并对多个时间窗口和多个模型重复 baseline、MemWeave auto、oracle 三组实验，报告回答正确率、误注入率、首 token 增量和完整响应时间。本轮只完成一次固定 100 条 DeepSeek 对照，不能代替多轮生产验证。
