# 知识治理控制面

把“AI 帮忙整理知识”和“AI 自己判自己正确”分开。已有的分级准入、客观经验验证、负例隔离和 LFHV 继续工作；这个控制面只补充管理流程，不替换 Hook，不新增 Agent 接入。

## 怎么用

1. 本地安装可选网关：`pip install 'memweave-runtime[mcp]'`。源码用户可在仓库运行 `pip install -e '.[mcp]'`。
2. 在支持 MCP 的客户端添加 stdio 服务，命令为 `agent-knowledge-mcp`；明确设置 `AKB_AGENT_ID`、`AKB_PROJECT_KEY` 和 `MW_DB_PATH`，数据库与本地 Runtime 使用同一份。用客户端自己的 MCP 配置入口，不修改 Hook。
3. 对 AI 说：“查看这个项目的候选和证据，重复的归并，有冲突的单独列出；先生成治理预览。”
4. AI 通过 `knowledge_review_queue` 查看候选，结合 `knowledge_search` 和 `knowledge_get` 查看已采纳知识、原文、证据和版本，再调用 `knowledge_governance_preview`。当前没有额外付费后台治理模型，使用的是你当前客户端的 AI。
5. 从 `memweave ui` 打开知识管理，点击“AI 治理预览”。逐项查看原文、来源证据和冲突，确认后执行。不是看见 AI 写了“测试通过”就自动批准。
6. 操作历史保留在同一页面。需要时点“撤销本次治理”；有后续知识活动时不会强行恢复旧状态。

网关工具返回的 `review_path` 是不带凭据的 `/governance`，请从本地管理页进入。不要把 Runtime Token 发给模型、放进聊天记录、Git 配置或分享链接。

## 哪些自动做，哪些要确认

| 动作 | Core 边界 |
| --- | --- |
| `merge` 归并 | 候选与已验证的 `active/stale` 知识正文完全一致，类型与作用域一致，目标未失效、未替代、无未解决冲突；项目知识可免人工确认。不是关键词相似或同文件路径就合并。 |
| `approve` 批准 | 用户在管理页确认后，将待审候选或隔离项转为 active。存在版本硬冲突时拒绝普通批准。 |
| `quarantine` 隔离 | 用户确认后停止普通召回；不因一句“不对”批量误伤整个上下文。 |
| `archive` 归档 | 用户确认后归档 active/stale。归档不是删除，也不证明知识错误。符合条件时仍可通过 LFHV 恢复。 |
| `supersede` 替代 | 必须选择同一结构化断言槽位中准确的一条冲突旧版，由用户确认；新版生效与旧版归档同事务完成。多旧版复杂冲突留给原有详细审核，不猜测覆盖。 |

用户级知识跨项目共享，因此即使正文完全一致，归并也要求确认。归并不删除原文、来源会话或证据，候选保留为归档前身并链接到已采纳版本；没有把“重复出现”累计成验证次数。已被替代的前身不能借 LFHV 再次生效。

当前自动执行只覆盖确定性重复候选归并。泛化语义合并、用词面信号自动替代、把“可以”当成修复验收、凭同轮成功命令批准任意结论，都不在范围内。用户要求长期保留的不确定内容仍保留原文限定，不因人工确认变成无条件事实。

## 执行与撤销

- 一份预览最多 20 项操作，有效期 24 小时；内容不可编辑，需要更改就重新生成。
- 预览只新增计划，不修改知识状态、证据或命中统计。
- 执行前在写事务中复查知识、证据、生命周期审计与冲突版本；变化、删除、跨项目访问、过期预览都被拒绝。批次全成功或全回滚。
- 后续反馈、使用计数、召回、编辑或冲突变更，都可能让预览或撤销失效。这是有意保守，不会覆盖别处刚处理的结果。
- 每次变更记录计划、操作者、前后状态及生命周期审计。撤销保留历史审计，将本次批准/拒绝证据标为 `reverted`，恢复本次变更前的状态和计数；不把已撤销的批准当成有效确认。
- MCP 只能读取、预览和执行已有权限的计划，不提供批准和撤销工具。旧 `knowledge_feedback` 在 MCP 中只允许 `used`，模型不能通过自填 `user_approval` 或测试引用绕过审批。已有可信 Hook/Runtime 客户端的客观验证接口不变。
- Runtime 管理接口继续要求本机 Bearer Token；批准、撤销接口额外要求显式确认。这里是工具权限与职责隔离，不是针对拥有本机 Shell/Token 的恶意 Agent 的安全沙箱。
- 管理页通过现有 SSE 接收计划与知识变更，跨进程更新。打开原文证据时保留阅读状态，关闭后同步列表；执行仍以 Core 的最新校验为准。

Core 模块为 `governance_control.py`，通过 `KnowledgeBridgeService` 暴露；Runtime API 和可选 MCP 都调用同一份实现。网关不提供批准入口；不额外启动执行器，不让 MCP 成为学习或检索依赖。
