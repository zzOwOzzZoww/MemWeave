# 分级知识治理

目标不是让模型替用户决定什么领域重要，而是减少没有必要的候选和逐条审核。规则适用于所有 Agent 的统一学习链路，不按技术、求职、生活等话题分流。

## 三种处理结果

| 结果 | 条件与示例 |
| --- | --- |
| 自动生效 | 用户完整原文明确表达稳定、无条件的偏好/决定，例如“以后默认使用简体中文解释技术问题”。不必额外说“记住”，但不能有相关已采纳记录、冲突或敏感内容。 |
| 保留待审 | 有原文支撑的普通事实、需要核对的规则、局部引用、相关规则变更，以及用户明确要求长期保留的临时信息或未确认事项。 |
| 不生成候选 | 默认丢弃临时活动、一次性状态、待定方案、不确定推测和纯问题。拒绝原因写入学习记录，不把待处理垃圾转移到候选池。 |

新知识仍先发布为 `candidate`；通过自动证据门槛后才晋升 `active`，不是让提取模型直接写入 Active。已存在的、绑定同一验证命令的失败后成功经验，继续走专用客观证据校验；普通知识不能借同轮某条命令成功自动晋升。未解决但确实观察到的失败，可以留下有限的待审经验，不能虚构根因。

## 长期保留，不等于长期为真

- “今天我正在准备面试”：默认不生成候选。
- “我猜是缓存导致的”：默认不生成候选。
- “请长期记录：我猜这个问题可能是缓存导致的”：只生成待审记录，正文带“尚未确认，不得当作事实”。
- “请持续跟踪：今天我正在准备面试”：只生成待审记录，正文说明它只描述来源会话时的临时状态，不代表当前状态。

长期保留请求必须在这条知识引用的用户证据中，不能借用同轮另一件事的“请记住”。示例和引用里的指令不算用户授权。明确拒绝保存和敏感信息拦截优先于保留请求。上述例外不授权保存秘密、原始私人会话或把模型猜测当作事实。

待审记录不参加普通召回。人工以后批准了这类记录，正文中的时效/不确定性限定仍保留；这次没有新增定时跟踪服务、有效期调度器或“批准后就是真的”的假设。

## 实现与边界

- 提取模型按每条证据给出 `retention: durable | temporary | uncertain`，辅助识别语义上的临时性和不确定性；它不能批准知识。
- Core 的 `admission.py` 做本地准入检查；`decisions.py` 验证原文引用、适用范围和自动晋升资格；`learning_engine.py` 在候选发布前执行这些检查。
- 检查引用所在的句子，防止截掉“今天”“我猜”等限定词后把局部片段伪装成稳定事实。逐条处理，一条临时记录不会让另一条独立的长期规则一起丢失。
- 句界同时识别中英文句末，引用已包含句末标点时不再拼接下一句；英文缩写、版本号和路径里的点不作为简单切割依据。独立事实可留作候选，但不会从混杂的整轮文本里自动删掉风险内容、拼出一条可生效知识。同一句中的限定词仍保留。
- “I remember …”“I can always use …”等自述不算对 Agent 的长期授权；自动生效要求有明确的指令结构。长期词和动作词不能跨句凑出授权，一句指令也不能替同条记录里另一句普通叙述背书。识别不清的表达仍留待审核。
- 自动晋升保持既有去重、项目范围、版本冲突及事务内复查。遇到相关已采纳知识时退回人工审核，不自动覆盖。
- 模型的 `durable` 标签和高置信度都不是证明。自动晋升目前只覆盖有限的明确用户规则，以及已有的专用经验验证，不覆盖任意开放领域事实。
- 本地检查是有边界的语言规则，不是通用语义真值判定器。兼容旧 reviewer 缺少 `retention` 的输出，但仍拦截可识别的临时/推测内容；无原文引用的旧提案不会自动晋升。
- 当前编译器版本为 `memweave-compiler-v7-evidence-scoped-admission`，避免新的准入检查被旧编译缓存直接跳过。不批量重写或删除历史知识，也不自动清空旧候选；本次修复不改变检索策略版本或 LFHV 证据。

### 2026-10-16 后续审查：证据、授权与范围必须对齐

上一节是 v6 的历史验收，不代表后续新增边界已覆盖。v7 针对继续审查发现的四类问题收口，不扩展治理权限：

| 问题 | 修复后的行为 |
| --- | --- |
| 一条长期指令替逗号、连接词后的普通事实背书；授权检查删掉引文，但入库存整条原文 | 按子句检查授权。混合事实、引文和代码只保留待审，不自动生效。新句子必须有自己的长期指令，不能借上一句的“以后 / always”；同句明确的命令续句仍支持自动生效。 |
| 只引用项目事实，却从同轮另一句“所有项目”取得用户级范围 | 范围只取该条完整引用及其限定上下文。每条子断言都明确跨项目且没有局部限制，才允许 `scope=user`；引文、局部与全局范围混杂时保守使用 `project`，人工批准也不会自动扩大范围。 |
| 普通 token 预算、tokenizer、密码哈希等技术描述被当成凭据；真正敏感拒绝又显示成证据错误 | 区分技术概念、凭据值与保存凭据请求。保留原脱敏检查，敏感请求标记 `sensitive_storage_request`，敏感值标记 `sensitive_content`；伪造/无效引用仍是 `invalid_source_evidence`。 |
| “This is temporary / I am not sure / 尚未验证”等相邻短句被漏掉或保留后未参与分类 | 收集和分类共用限定语规则，连续的前后限定也一起检查。未明确要求长期保留时不入候选；明确要求保留也只进待审，正文带时效或不确定性警示。 |

提取提示同步要求模型给出独立、完整的原文断言，保留否定、范围、时效及相邻限定，不能通过剪掉限制绕过准入。一句敏感请求不会阻止同轮另一条独立、正常的事实进入候选。旧适配器导入保持兼容，所有决策仍在 Core；MCP 只是可选入口，不接管准入权限。

**拒绝计数口径：**纯敏感保存请求可以在调用提取模型前被抑制。此时 `rejection_reasons.sensitive_storage_request=1` 表示一次会话轮次抑制，`reviewer_proposals`、`rejected_proposals` 和 `proposals` 均为 0；不是凭空拒绝了一个模型候选。进入提取阶段后，拒绝原因才按具体提案计数。管理页补齐敏感、临时、不确定及拒绝保存等原因标签。

验证先覆盖新增边界，再覆盖学习、经验验证、治理控制面、Runtime API 与公开评测脚本的定向回归，最后运行全部 `tests`。用例使用临时数据库，不触碰实际知识库；固定模型 HTTP 响应经过 `DeepSeekReviewer → Runtime API → SQLite` 验证解析与准入链路，不把它当作真实模型分类质量或真实客户端验收。

旧公开评测是固定原文提案的准入审计，并没有验证真实模型提取、MCP 规划质量或实际人工工作量。本轮不重写公开评测结果，不声称自动审核准确率或人工节省比例提高；没有部署运行中的 Runtime、迁移历史记录或发布到 GitHub。

### v8：混合消息按独立断言保留，不能按整轮一刀切

v7 完整公开历史复测暴露了另一类误杀：`My project uses SQLite. Can you explain WAL?` 里，确定事实被后面的提问一起过滤。不能靠放开整轮准入修复，否则猜测、临时限定也会跟着入库。

Core 现在只在有真实原文引用的用户提案因临时性或不确定性被拒时，尝试保留最多三段、每段不超过 600 字符的独立陈述。每段再回原始消息补查限定；只存模型已引用的内容，不从消息别处借事实。普通逗号不能任意切开，`Today,`、`Maybe,` 和“这只是猜测”不能被剪掉。

这条保留路径固定为 `candidate / project`，不继承整轮长期授权、跨项目范围或测试成功信号；标题改用实际保留正文，删除被丢弃问题和猜测的检索词。模型标为临时/不确定、用户拒绝保存、引用代码及包含敏感内容的同条提案不能走该路径。它是有限语言规则，不是通用事实抽取或真值判断。

编译器升级为 `memweave-compiler-v8-independent-assertions`。上文 v6/v7 的验收保留为历史，其中“整轮混合内容可能整体拒绝”新增上述受限例外；其他授权和安全边界不变，不修改检索、LFHV、Hook 或生产知识。

完整复测另用 [ASSERTION_REPLAY.md](../evaluation/longmemeval-governance-v1/ASSERTION_REPLAY.md) 冻结内容覆盖口径：整条保留、仅部分保留和无保留必须分开。官方标注在消息级，保住一句不能冒充整条答题证据已经恢复。

### v9：先核验片段质量，再控制重复候选

v8 新增候选仍可能丢掉关键事实，不能将“存了一句”视为成功。进一步原文审计发现：关系从句 `which …` 被当作独立问句边界，过去时/缩写/话语前缀掩盖计划或求助，脱离主体的 `it / this / that` 片段也可能占据候选预算。

本轮将上述修复限制在独立断言 fallback：保留完整关系从句，仅在明确问句结构处分割，剔除可识别的计划/请求和孤立回指。普通原文提案的授权、敏感和范围规则不放宽，也不根据标准答案决定留哪句。编译器为 `memweave-compiler-v9-assertion-quality`。

学习入口另补精确候选复用：正文完全一致、类型/范围/项目/说话人一致、状态是未过期待审且未被替代，才可忽略模型标题差异复用同一条记录。第一条的正文、标题和索引不被新标题覆盖；每轮来源仍通过编译链接保留。不跨项目，不模糊合并，不借用已生效知识的批准，不复活隔离/归档记录。手动发布和治理控制面的显式合并保持原行为，不批量迁移历史知识。

新增 [QUALITY_AUDIT.md](../evaluation/longmemeval-governance-v1/QUALITY_AUDIT.md) 冻结完整复测及离线内容审计：标准答案字面留存仅作定位信号，不当语义判分；答案本就不以原字面出现的项不冒充错误或成功。没有独立判分标签，不报告候选正确率或人工节省比例。

**不能把这轮写成整体质量或召回提升。** 待审记录合计减少 19.43%，但标注消息有内容留存从 664/832 降到 586/832；两者都不是语义准确率或正确审核率。字面诊断找回 6 条、丢失 7 条，净少 1 条。全部原有 full 消息保持 full；原 partial 中 15435 次变为 filtered（标注 87 次），另有 527 次 filtered 变为 partial（标注 9 次）。这些分布不能证明每条过滤都正确。

对 v8 partial 标注消息按题型、固定 SHA 顺序抽取 21 条，并复核全部 13 条字面类别变化。看到的收益是关系从句不再被截断、Nike 等明确偏好保留而求助句被移除；代价是计划中嵌入的既有偏好、拥有关系或历史事实也可能一起丢失。独立断言的语言覆盖仍有限，未知项不能算成功。上述复核由单一助手完成，不是独立人工金标准，不据此计算候选正确率。

这说明 Core 的保守 fallback 不能代替真实提取模型拆解复杂句。后续如改进，应让提取器产出带主体、原文引用和完整限定的独立事实，并单独验证其质量；不能去掉计划/不确定性拦截，或按本数据标准答案加例外。未做真实模型提取验收前，保持本轮不部署，不宣称嵌套事实漏保留已经解决。

公开回放使用固定标题的原文提案，不能从候选减少量中单独推断“模型换标题去重”收益；该能力由临时数据库的不同标题、并发、来源保留和状态隔离用例验证。同题重复保留正文出现次数从 536 降到 499，也不等于重复记录数或节省的人工操作数。

性能同样未达成改善：完整耗时由 1210.64 秒增至 1590.24 秒，并发 learn P95 上升。两次墙钟和并发延迟受机器负载影响，未做受控性能归因；不能宣传延迟下降，也不能把它当作检索耗时。检索、LFHV、Hook、适配器和治理权限保持不变，没有迁移历史知识、重启生产 Runtime 或上传 GitHub。

### v10：拆清独立事实的证据边界，不能靠删除限定词放行

v9 的一个具体问题是：提取器即使只引用 `our service uses SQLite.`，Core 也会把同句 `I'm considering a cache migration,` 补回，事实再次被意图框架连带处理。整轮提案的兜底同样缺少结构性的并列边界。

本轮要求 reviewer 在同一次调用中分别提供自含、逐字引用的独立事实，不新增模型调用。Core 仅在两侧有可识别主体与谓语的结构性并列建立边界，并在当前提案内复用原文位置索引。关系从句、孤立回指、引文、括号、前置条件、猜测和时效不能借此拆成事实；没有自含原文断言的嵌套拥有关系仍不推断。

拆分后保存的仍是 `candidate / project`，不继承整轮批准或全局范围。检查同时覆盖落库正文：不能识别完完整上下文，却把裁掉 `not / only in tests / 不用于生产` 的半句话存进去。完整有限制的事实可以待审；明确长期保留的临时/不确定事项继续走原有警示路径，范围仍由原有元数据保护。有限语言规则不能穷尽所有自然语言表达。

候选正文复用补上部分表达式索引，以项目、范围、类型、长度、前 128 字符和说话人缩小查询，再检查完整正文、待审状态、过期及替代条件。前缀碰撞、中文和 NUL 均不能导致不同正文合并；手动发布的身份规则不变，也不批量改写历史数据。编译器为 `memweave-compiler-v10-atomic-evidence`，完整复测协议见 [ATOMIC_EVIDENCE.md](../evaluation/longmemeval-governance-v1/ATOMIC_EVIDENCE.md)。

### v10.3：修复真实提取输出与 Core 治理之间的衔接

上一轮真实模型试跑暴露的问题不全在提取器：模型给出了有用内容，Core 也可能因条件表达、引用粒度或恢复状态将它误杀；模型没返回完整响应时，又不能将异常当成“没有知识”。本轮只修这些衔接，不增加治理权限或 Agent 接入范围。

| 问题 | 修复与边界 |
| --- | --- |
| 经验条件必须逐字连续出现；“Linux 不适用”又可能误拒 Windows 请求 | 简单正向条件按平台、实体和任务锚点检查，兼容中文紧邻英文。排除项识别真正被排除的主体；疑问、双重否定、混合平台保守拒绝。正文仍保留原条件，不做任意语义改写。 |
| 明确复合指令被局部引用拆散，或全局范围跨句泄漏 | 支持有限的明确并列长期指令。仅当同类型提案的精确引用合起来覆盖完整指令时，才共用整段原文；缺事实、混入猜测或不同来源均不借授权。全局范围只在同一句明确指令内共享。纯本轮任务指令不存作长期事实。 |
| “尚未恢复”导致客观失败观察也被过滤 | 对同轮引用的真实失败命令，只保存有边界的失败观察及重新验证清单，丢掉模型猜测的根因和修复步骤。无关检查通过、先成功后失败、末次状态未知都不能证明恢复；该路径仅进入 `candidate`。临时边界和拒绝保存仍拦截。 |
| 空响应、坏 JSON 或输出预算耗尽掩盖提取失败 | 响应必须有完整对象及 `proposals` 列表，拒绝截断、空内容和从坏外层捞嵌套提案。默认输出预算上限为 8192，可通过 `MW_REVIEW_MAX_TOKENS` 在 512–8192 内配置。失败交给既有队列最多三次、有退避地处理，不加模型内重试；耗尽后仍明确失败，不伪装零提取。 |

| 检索元数据夹入推理杂质或凭空主体 | 检索别名规范为有数量/长度上限的去重词条，过滤明显指令和问句杂质；主体词必须实际存在于落库正文。原始引用和来源链仍保留，不将别名当证据。 |

编译器升级为 `memweave-compiler-v10.3-review-boundaries`，决策策略升级为 `memory-decisions-v8-experience-conditions`，避免旧缓存跳过新边界。没有批量重新审核历史记录。
