# MemWeave v0.3 Runtime 架构验收记录

> 这是 2026-09-18 的阶段性记录。当时 Codex 自动 Adapter 尚未接入；后续实现见 [`双向Adapter实例验收_20260920.md`](双向Adapter实例验收_20260920.md)。

验收日期：2026-09-18

## 验收目标

验证 Claude Code 自动学习主链路已经脱离 MCP：Hook 通过带鉴权的本地 Runtime API 完成召回和学习，Core 独立处理知识生命周期，关闭 MCP 不影响整个闭环。

## 实际链路

```text
Claude Code
  → UserPromptSubmit / Stop Hook
  → MemWeaveRuntimeClient
  → 127.0.0.1 随机端口 + Bearer Token
  → FastAPI / Pydantic / Uvicorn Runtime
  → Learning、Governance、Context Core
  → SQLite WAL + FTS5
```

MCP Server 没有参与本次验收。启动脚本使用空 MCP 配置和 `--strict-mcp-config`，只读取项目级 Claude 设置。

## 自动化验证

单元与 API 测试：

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m unittest discover -s tests -v
```

结果：14 个测试全部通过。新增 Runtime 测试覆盖：

- 未携带 Bearer Token 时返回 `401`；
- 业务校验错误返回结构化 `422`；
- 不经过 MCP 完成 `candidate → verified → active → search`；
- Claude transcript 学习和下一会话召回跨越 Runtime API 边界。

真实子进程 smoke：Runtime 在随机端口启动，Hook 经 HTTP 返回正常结果，`/v1/health` 返回 `memweave-runtime 0.3.0`，退出后进程成功回收。

## 结论

v0.3 已证明 MemWeave 的自动学习不依赖 MCP 工具选择或 MCP Server 生命周期。Runtime 建立了独立进程、版本化 API、数据合约、认证、健康检查和故障边界，Agent Adapter 只负责协议转换。

当前 Token 只验证“调用方持有本次 Runtime 凭证”，尚未实现每个 Token 的 Agent、项目和权限声明；请求体中的 `agent_id` 仍属于受信 Adapter 输入。Codex 自动 Adapter、后台任务队列、知识版本治理和 DPI 对照评测仍是下一阶段工作。
