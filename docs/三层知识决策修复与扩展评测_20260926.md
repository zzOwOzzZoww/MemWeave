# MemWeave 三层知识决策修复与扩展评测

日期：2026-09-26。状态：代码已修改，回归与扩展测试已执行，正式本地 Runtime 已加载新版并通过健康检查。

本轮根据 [15 案例基线评测](三层知识决策15案例基线评测_20260926.md) 修改准入、注入和 LFHV 恢复。测试使用隔离 SQLite 与合成对话；部署阶段另行备份正式数据库，没有把测试知识导入用户知识库。

## 1. 实际改动

### 本轮是否使用知识

新增标准库模块 `decisions.py`，供检索、最终上下文生成与恢复治理共同使用。

- 识别明确的知识排除、整轮不使用记忆、限定的新话题，以及“不用重复，转而解释另一问题”等请求。先缩小本轮检索文本，避免否定句中提到的词反而成为强检索信号。
- 排除判断发生在候选成为扩展种子之前，并对扩展结果再检查。被拒绝的页面偏好不会再给 sibling 等扩展提供种子。
- 普通知识解释在没有个人偏好/默认设置等使用信号时，不自动应用 preference。这个规则不等于理解所有任务意图。
- 记录明确声明自身已经废止时，不用于当前决定；用户询问历史决定时保留追溯能力。“新记录提到旧规则废止”不等于新记录废止，条件句与引用也有反例测试。
- 排除项目内某个主题时，不能只因另一条知识也带同一个项目名就一并屏蔽。
- `reuse.start` 在最终生成上下文时再次检查完整 prompt；旧策略的同轮上下文缓存不绕过新策略校验。内部 trace 记录策略版本和拒绝原因，不向用户对话暴露内部标识。

四层检索仍是“候选生成 → 扩展 → 仲裁 → 截断”，没有新增 embedding 模型、向量数据库或查询时模型请求。既有 FTS5、别名扩展、锚点和来源追踪继续使用。

### 知识是否进入候选、是否自动采纳

内置 DeepSeek Reviewer 为普通知识提供 `source_quotes` 和来源角色。Adapter 校对引句是否实际存在于对应原文中，以准确引句构造存储正文，而不是保存模型扩写的建议。无证据猜测且没有实际工具工作的轮次，可以在调用 Reviewer 前跳过。

仅对以下窄场景自动采纳：

1. 知识类型为偏好或决策。
2. 引句完整覆盖用户本次简短请求；用户明确要求记住/保存，并表达长期、默认或正式决定。
3. 不包含未决定、问句、假设、引用、示例或明确不保存的情况。
4. 根据原文确定范围；明确跨各项目才自动设为用户级，否则收紧到项目级。
5. 没有检索到相关已采纳知识；写事务内再次检查，防止两个相互关联的候选并发自动批准。

这条晋升路径的证据是用户本人对持久偏好/决定的明确授权，不是“模型觉得可信”。遇到可能相关的现有知识时，仍交人工核对；目前冲突筛查是保守的词面检查，不保证识别任意同义矛盾。

有工具工作支撑的助手原文可形成待审观察，不能因为有工具就自动确认全部内容。结构化经验仍保留已有失败→成功证据流程。旧自定义 Reviewer 未提供引句时维持候选兼容路径，不获得新的自动采纳资格；内置 Reviewer 对普通无引句输出不入库。

编译器版本已更新，使去重身份包含这次提炼规则变化；本轮没有主动重新编译用户全部历史会话。

### LFHV 是否恢复归档知识

- 探测经过相同本地使用判断。明确废止的记录即使可供历史查询，也不因此获得恢复资格。
- 同一规范化查询在记录的最多 32 个摘要窗口内只计一次。窗口有界，不保存查询原文；不声称做到了无限历史或语义同义去重。
- 影子证据绑定策略版本，以及知识标题/正文摘要。旧版影子记录保留，但没有新版有效证据时不能直接恢复；修改知识后需要重新探测。
- 在状态迁移的写锁内复查内容摘要、废止判断与状态，防止探测后内容变化仍被恢复。
- 新增 `last_restored_at`，给恢复记录一个有限的治理宽限期。恢复本身不再调用 `mark_hits`，因此不会冒充一次真实上下文注入。

默认恢复门槛仍是一条合格探测，由显式恢复治理触发。它代表可能需要再次提供这条知识，不代表已验证任务收益，也不代表需要多次真实成功使用才能恢复。

## 2. 验证规模和结果

| 测试集 | 规模与执行方式 | 修改前 | 最终结果 |
| --- | --- | --- | --- |
| 原始 15 案例 | 保留原输入与预期；准入真实模型复核，注入/归档隔离复核 | 6 个不符场景、2 个自动采纳缺口 | 原问题得到修复；长期归档正文淘汰仍未实现 |
| 扩展决策矩阵 | 120 组：80 注入组合、20 归档组合、20 对话；两个 Adapter，共 240 次观察 | 同一批本地 200 次中符合 116 次，不符 84 次；未付费复跑旧版准入 | 240/240 符合冻结预期 |
| 混合知识库挑战 | 20 个问题，每库同时放 6 条不同主题/版本知识，双向共 40 次 | 18/40 符合必需/禁止项约束 | 40/40 符合这些约束 |
| 原有 100 条检索基准 | 115 条基准知识加 1,000 条干扰知识；100 问题重复三轮，各版 300 次 | 270/270 正例召回目标，30/30 负例零注入 | 对应指标保持相同 |
| 完整代码回归 | 包括 Hook、Runtime、队列、安装配置、生命周期、范围隔离、经验合约等 | 本轮初次发现 1 个旧测试依赖列顺序 | 最终 385 passed，9 subtests passed |

扩展决策矩阵最终运行使用 `deepseek-flash`，实际模型调用 **36 次**：40 次准入观察中的 4 次明确无证据猜测被本地跳过，其余真实调用。20 次正例均自动成为 active，正文与用户原句一致、scope 符合预期；20 次负例均无候选。API 无执行错误。

120 组并不是 120 种独立行为：它包含相同意图模板在多个主题上的组合。混合库集在发现新失败后也用于调整，因此两者都是开发回归集，不是盲测或真实流量分布。不能把 240/240 写成“MemWeave 真实准确率 100%”。

混合库按 required/forbidden 约束评分：必须召回的项不能缺失，明确禁止的项不能注入；未列入约束的额外内容并非每题都被判错。因此 40/40 也不代表所有返回知识的精确率 100%。

原有 100 条基准主要检验目标召回和无知识负例，跨语言正例含显式检索别名；不证明任意同义问题都能召回，也不代表下游任务成功率。

## 3. 扩大测试后新增发现与修复

第一次 120 组组合测试通过后，新增混合库挑战只有 30/40 符合预期：

- 询问材料吸热时，页面偏好可能被拒绝，另一条语言偏好却经扩展进入上下文。
- 没有明确说“与偏好无关”的物理题、语言起源问题，仍会匹配个人偏好。
- “不用重复。请介绍 SQLite WAL”没有命中最初的话题切换形式。
- 用户指出这不是某项目的配置问题时，该项目多个规则仍进入候选。

据此增加候选种子前过滤、一般解释与偏好应用区分、替代话题切换形式和明确项目排除，复跑到 40/40。初次失败原始结果保留在 `mixed-first`，没有覆盖成通过记录。

另补充了引句造假、用户不保存、引用与双重否定、条件废止语句、并发自动采纳、重复探针、旧策略证据、知识修改后的恢复竞争等代码回归。Schema 增加字段后，旧删除测试的裸 `INSERT ... VALUES` 改为显式列名，原有删除和清理断言继续保留。

## 4. 性能观察

同样的 1,115 条知识、100 个问题、三轮本地 Adapter 测量：

| 测点 | 修改前 | 修改后 |
| --- | ---: | ---: |
| Adapter P50 | 44.196 ms | 45.329 ms |
| Adapter P95 | 59.318 ms | 59.415 ms |
| 主要检索测点 P50 | 14.741 ms | 15.084 ms |
| 主要检索测点 P95 | 27.116 ms | 27.690 ms |

本次没有观察到明显的本地延迟增加；P50 约差 1.13 ms，P95 约差 0.10 ms。但前后是分进程按顺序运行，包含机器背景噪声，不是随机交错的因果实验，不能把差值精确归因为新规则成本。

Adapter 测量包括本地召回与记账，不包括真实客户端 Hook 启动、网络推理和模型预填充，**不是首 token 耗时或启用/关闭 MemWeave 的 TTFT 差值**。本次规模也不能代表百万级知识库。

## 5. 已知边界

1. 本地判断识别有限的明确语言形式，仍可能漏掉隐含意图、长上下文指代和未声明的矛盾。没有新增语义模型就不应宣称完整理解“值不值得使用”。
2. 当前废止判断侧重记录明确声明自身失效。仅有两个不同数字、没有版本关系标记时，不能可靠推断哪条是最新真值；自动采纳相关项会保守留待审核。
3. 原文引句证明来源一致，不证明用户说的事实客观正确；个人偏好/本人决定的授权与外部事实验证应分开。
4. 截取原文可以避免正文扩写，模型生成的标题和检索别名仍可能不够准确，需要后续独立评测。
5. LFHV 的规范化去重是有限窗口的词面去重，换一种说法仍可能算另一条需求信号。恢复价值尚未通过真实任务 off/auto/oracle 配对实验验证。
6. active 治理与影子账本有界，不代表全部数据库字节有界。归档正文与其他审计数据的长期保留/淘汰仍需独立策略，不在本轮自动删除真实知识。
7. 本次主要验证 Core 与原生格式 Adapter。真实 Codex/Claude 连续对话体验、客户端实际首 token 和长期质量仍需后续实测，不能以接口返回上下文替代。

## 8. 自然表达边界复评

为验证规则不是只对固定模板生效，新增了 25 条自然语言查询（每条分别经过 Codex 与 Claude Code 两个 Adapter，共 50 次注入观察）以及 20 条自然语言准入请求。案例覆盖口语化偏好、项目切换、一般性解释、临时例外、明确排除项目配置、明确排除个人偏好、引用转述和敏感凭据。

最终结果：

- 知识注入边界：50/50 符合冻结预期，注入判断通过率 100%。明确说“另一个项目”“新项目”“一般产品设计原则”或“不用我的常用风格”时，项目级知识/个人偏好会在最终仲裁阶段被拦截，不会因 FTS 命中或扩展路径重新进入上下文。
- 自动采纳边界：20/20 符合冻结预期，其中 12 条自动采纳、4 条进入人工审核、4 条直接拒绝。API Key、密码、token 等敏感存储请求在 `grounded_user_proposal()` 内直接拒绝；引用、假设、条件句和临时安排不自动采纳。
- 该评测仍是人工编写的合成自然表达集，不是线上流量抽样，也不是通用语义理解准确率。100% 仅说明当前冻结案例集没有回归，不能外推到任意长上下文、隐含指代或同义改写。

新增回归用例固定在 `tests/test_memory_decisions.py`，覆盖项目范围排除、个人偏好排除、敏感信息准入拒绝和引用转述保持人工审核四类边界。
