# MemWeave Codex ↔ Claude Code 双向 Adapter 验收

## 目标

在不依赖模型主动调用 MCP 的前提下，让 Codex 和 Claude Code 接入同一个本地 Runtime：

```text
Claude Code UserPromptSubmit ─┐
Claude Code Stop ─────────────┤
Codex UserPromptSubmit ───────┼─> Runtime API ─> Learning/Core ─> SQLite
Codex Stop ───────────────────┘
```

两侧使用同一个项目键 `claude-codex-mvp` 和数据库 `data\knowledge.db`，但每条记录保留来源 Agent。Adapter 只负责解析各自的会话格式：Claude 解析 Claude transcript JSONL，Codex 解析 rollout JSONL；候选提炼、客观证据门禁、召回反馈和生命周期治理完全共用。

## 已实现

- Codex 全局配置：`~/.codex/hooks.json`；信任状态：`~/.codex/config.toml` 的 `[hooks.state]`
- Claude 项目级配置：`demo\self-learning-workspace\.claude\settings.json`
- Codex 输入：`prompt`、`session_id`、`transcript_path`
- Codex 输出：`hookSpecificOutput.additionalContext`
- Codex Stop 解析：`function_call`、`function_call_output`、`task_complete`
- 共用 Runtime：Bearer Token、FastAPI、SQLite WAL、FTS5/BM25
- 共用证据门：无成功客观事件的候选不会进入正常召回
- Stop Hook 使用同步模式，确保 Runtime 在客户端退出前完成本轮记录；模型复盘耗时不进入正常首 token 路径

## 启动

先设置用户级 `DEEPSEEK_API_KEY`，然后分别在两个 PowerShell 窗口启动：

```powershell
# 从 MemWeave 仓库根目录运行
.\demo\start-bidirectional.ps1 -Agent codex
```

```powershell
# 从 MemWeave 仓库根目录运行
.\demo\start-bidirectional.ps1 -Agent claude
```

两个进程可以同时运行，分别启动自己的回环 Runtime 端口，但写入同一个 WAL 数据库。关闭 MCP 不影响自动召回和学习。

## 隔离验收

```powershell
.\demo\run-bidirectional-adapter-smoke.ps1
```

验收脚本使用临时数据库和两个确定性验证候选：

| 检查 | 结果 |
|---|---|
| Claude 来源知识被 Codex Hook 召回 | PASS |
| Codex 来源知识被 Claude Hook 召回 | PASS |
| 无关请求不注入知识 | PASS |
| 不使用 MCP | PASS |

另外，在真实 Codex CLI 隔离工作区执行过一次 `codex exec --json`，模型在收到 Hook 注入后返回 `LIVE_HOOK_OK`，证明 Hook 已进入真实 Codex 上下文。当前桌面版使用全局 `~/.codex/hooks.json`；修改配置后需要重启 Codex Desktop，才能让桌面进程重新加载 Hook。每次调用的 started/completed/failed 证据保存在 `data/knowledge.codex-hook-runs.jsonl`。

## 边界

当前是单机、本地全局 Hook Adapter 实例，不会读取另一个 Agent 的原始私有会话；只共享经过脱敏、候选提炼和客观证据验证的知识。来源 Agent 与请求 Agent 是两个不同维度：Claude 产出的知识仍以 `source_agent=claude-code` 保存，但 Codex 可以通过同一项目键召回它。当前检索仍是 FTS5 关键词检索，尚未加入向量召回、语义冲突合并和过期知识压缩。
