# 对话生命周期计时

日期：2026-09-24。目的：将每轮首 token 耗时、整轮耗时保存为运行记录字段，和知识检索耗时分开，不改变召回算法。

## 数据位置与口径

字段加在原有 SQLite `reuse_traces` 行中，不新增知识记录、全文索引、向量或逐 token 日志。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `ttft_ms` | INTEGER，可空 | Codex 原生 `time_to_first_token_ms` |
| `response_total_ms` | INTEGER，可空 | Codex 原生 `duration_ms` |
| `response_started_at` | INTEGER，可空 | 原生轮次开始时间，Unix 秒 |
| `response_completed_at` | INTEGER，可空 | 原生轮次结束时间，Unix 秒 |
| `timing_source` | TEXT，可空 | 当前为 `codex.task_complete` |
| `timing_status` | TEXT | 已采集、部分缺失、未采集、不可用、中断、异常或来源不匹配 |

Codex 官方协议对首 token 的定义是轮次开始至第一个模型 token，整轮耗时是轮次开始至结束。它们不是逐次模型请求的耗时，也不保证等于屏幕第一段可见文字及最后文字的渲染耗时。任务中工具、等待等因素会影响整轮耗时，不能把完整数字归因于 MemWeave。

本机已有 `task_complete` 携带这些字段；之前 MemWeave 没有读取，所以页面显示未测量。现在读取原生整数，不用助手消息落盘时间或知识提炼完成时间推算。不改原有 `completed_at` 的含义，该字段仍用于复用记录完成。

## 采集路径

1. 提交问题时沿用已有记录；不读取计时日志、不启动计时线程。
2. Stop 调用原有学习接口后，在 `finally` 中登记一个后台采集任务，即使提炼失败也可以采集已有轮次的计时。
3. 按指定 transcript 读取头部的 session metadata 和最多 512 KiB 尾部，核对 session 和 turn；只接受原生 `task_complete` 计时。中断另行标记，不计完整耗时。
4. 已有消息时间戳、外层脚本运行时间、错轮次或错会话都不作为证据。负数、非整数、首 token 大于整轮等异常不计入统计。缺失为 NULL，实际的 0 保留为 0。
5. 按原有唯一索引定位一行，后台执行一次字段更新。重复回调不能改写已采集数据，也不创建虚假 trace。

结束事件可能在 Stop 返回后才落盘，因此后台按 0.2、0.5、1、2、4、8、16 秒间隔重试，最多 7 次。队列上限 64，只有一个惰性创建的 worker，无任务时等待，不遍历所有会话。每次数据库连接及时关闭，避免 Windows 文件句柄占用。

当前自动采集属于本地 HTTP Runtime 实例。直接使用无 Runtime 的适配器不自动挂后台 worker；没有原生字段的 Claude Code 或其它 Agent 继续显示未测量。队列只在内存中，服务重启会丢弃未完成采集；字段不会伪填，已有日志可用时可以显式补采。

## 为什么不会增加检索算法复杂度

- `search`、FTS、扩展、仲裁、截断均不读取计时字段。
- 没有新的检索条件、排序因子或模型请求。
- 采集更新只涉及 `reuse_traces`，不改变知识库 revision，也不让 df 缓存失效。
- P50/P95 只在管理页请求 metrics 时计算，按 Agent 分组并返回各自样本数；NULL 不进入分母。
- 没有在前台等计时落盘，也没有每生成一个 token 就写数据库。

不能承诺物理开销为零：字段会占少量存储，后台尾部读取、SQLite 写入和指标聚合有 CPU/IO 成本，也可能与其它操作竞争资源。本次设计将这些成本与检索主流程隔开并设置上限；没有声称测得“零额外首字延迟”。

## 页面与历史数据

“实际复用证据”下新增“对话生命周期 · Codex”两张卡片：首 token P50/P95、整轮 P50/P95；每轮详情也显示两项耗时和采集状态。表格中的知识生命周期仍是 candidate/active 等知识状态，不与对话计时混用。

`scripts/backfill_turn_timing.py` 默认只预览，`--apply` 才回填。最多读取 200 条已有 unresolved Codex traces、4 MiB Hook 审计尾部和每个 transcript 512 KiB 尾部。仅按本来已经关联的文件、session、turn 补采，不重新提炼知识、不调用模型、不新增 trace。

本轮回填检查 32 条已有记录，精确补回 4 条；16 条在读取窗口内没有匹配结束事件，12 条没有可用审计路径。样本尚少，不能作为稳定性能结论：当时 4 轮的首 token P50/P95 为 5.965/27.911 秒，整轮为 12.308/36.519 秒。
