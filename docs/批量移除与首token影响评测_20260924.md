# 批量移除、审批锁定与首 token 影响评测

更新时间：2026-09-24。实现依据为本地源码和隔离测试。

## 1. 本次行为

已采纳清单新增复选框、全选本页、选中计数和批量移除。每次最多 100 条，与现有 20 / 50 / 100 分页一致。翻页后不保留其他页的隐藏选择；刷新或筛选后重新校验选择。操作前确认，通用知识额外提示会影响所有项目。

“移除”是永久删除，不是 Archived：删除正文、FTS 索引、审核证据、编译关联、经验统计和影子命中记录，同事务重建受影响项目的词桥，并由现有写触发器使检索统计缓存失效。已有复用缓存正文也清空，避免重复 Hook 重新发出已移除知识。查询到写入之间发生移除时，适配器会拒绝输出过期快照。

历史 Agent 事件、学习运行和复用审计仍保留，已删除条目在 trace 中标记 removed。这些保留记录用于审计，不参与正常知识召回。原来的 Agent 对话、已进入模型上下文的内容、备份不会被本操作抹除；删除后新对话如果重新总结相同内容，仍可能生成新的候选。这不是永久屏蔽主题或安全擦除功能。

SQLite 删除释放可复用页，数据库文件不一定立即变小。本请求不会在交互路径执行 VACUUM。批量移除是内容治理入口，不代表历史审计、备份也已经具有完整保留期限策略。

Core：`KnowledgeStore.remove_many`；Service：`remove_many`；Runtime：`POST /v1/knowledge/remove`。
请求必须携带认证、项目、knowledge_ids 和 `confirm_permanent: true`。先验证整批项目范围再开始删除；任何错误回滚整批。重复删除已不存在条目不会报错或重复减数。

## 2. 已批准状态不可重复编辑

详情使用最新服务端状态。Active 的批准按钮显示“已批准 · Active”，明确 `disabled=true`；审核意见 disabled，隔离操作隐藏。修复通用按钮 CSS 的 display 覆盖 hidden 问题。

前端限制程序触发与重复点击，后端对 Active 的重复人工批准返回 `already_active`，不增加 verified/adopted 或审核证据。真实测试、命令验证反馈仍可作为新证据记录，不与重复人工批准混淆。

## 3. 性能指标口径

首页改为“MemWeave 首 token 影响”，重点展示配对首 token 增量 P50/P95 和有效对照数。

每对实验：`delta_ttft_ms = ttft_on_ms - ttft_off_ms`。正数表示开启后更慢，负数表示此次观测更快。P50/P95 在每对差值上计算，不能用两个分组的 P95 相减。整轮差值也存储在指标接口中。

没有受控对照时显示“暂无对照样本”。普通会话原生 TTFT 和 duration 留在生命周期详情，不自动改名为框架耗时。

需要区分：

- 检索耗时：只覆盖检索路径。
- 完整 Hook 进程耗时：包含解释器启动、健康检查、HTTP 调用、审计，但不包含模型处理附加上下文的成本。
- 开关配对 TTFT 差值：希望观察的用户等待影响，仍混有网络、模型负载、缓存等不可完全控制的波动。

以前的 Hook 基准不能代替第三项，也不能把已经记录的不同普通会话直接相减。

## 4. 如何获得真实对照

1. 准备相同的纯文本任务、模型及推理配置、同一工作区快照、相同基础上下文与工具配置。使用独立新会话，防止上一轮回答泄漏到对照组。实验期间固定知识库快照，禁止把上一轮实验生成的知识写回下一轮条件。
2. 选择并记录基线。`framework_absent` 代表基线没有配置 MemWeave Hook；`hook_bypass` 代表 Hook 仍启动，但设置显式实验环境变量 `MW_LATENCY_BASELINE=hook_bypass` 后跳过召回、学习和审计。后者仍有解释器/导入开销，不能冒称完全无框架。
3. 不修改日常会话的全局开关。只在隔离实验配置或专用进程设置基线；这个版本不会偷偷把正常对话随机分流。
4. 交替执行 on→off 和 off→on，或者预先随机化顺序。同一任务多次重复，记录网络环境、缓存处理方式和失败/中断情况。建议至少 20 对作初步观察，但 20 对不是显著性或“足够轻量”的证明。
5. 等任务完成，从各自原生日志采集 session、turn 和 `task_complete`。缺失、中断、负数、TTFT 大于总耗时等情况不纳入有效样本；不要用 assistant 消息时间冒充首 token。
6. 使用导入脚本预览，再明确 `--apply` 保存。导入不会调用模型、生成知识或修改召回策略。

示例命令（manifest 路径替换为自己完成的实验清单）：

```powershell
# 从 MemWeave 仓库根目录运行
python -X utf8 scripts\import_latency_pair.py --manifest .\experiment-pair.json --database .\data\knowledge.db
# 确认预览和实验条件后再落库
python -X utf8 scripts\import_latency_pair.py --manifest .\experiment-pair.json --database .\data\knowledge.db --apply
```

manifest 结构如下。大括号占位内容必须替换，hash 字段为实际 SHA256（64 位小写十六进制），不可使用占位值或原始密钥。`prompt_hash` 由脚本从原生日志计算，不用填写。

```json
{
  "project_key": "claude-codex-mvp",
  "experiment_id": "ttft-controlled-01",
  "pair_id": "task01-repeat01",
  "baseline_mode": "framework_absent",
  "execution_order": "off_on",
  "conditions_confirmed": true,
  "conditions": {
    "model": "{实际模型}",
    "model_config_hash": "{固定的模型配置SHA256}",
    "base_context_hash": "{注入前基础上下文SHA256}",
    "environment_hash": "{客户端版本、工作区、工具和知识库快照配置SHA256}",
    "cache_policy": "{实际缓存控制方式}"
  },
  "on": {"transcript_path": "{开启组日志绝对路径}", "session_id": "{session}", "turn_id": "{turn}"},
  "off": {"transcript_path": "{关闭组日志绝对路径}", "session_id": "{另一个session}", "turn_id": "{turn}"}
}
```

脚本验证两边原生模型、provider、推理强度和实际提示词，并读取原生计时。基础上下文、缓存状态、是否真正禁用 Hook 等仍由实验操作者确认，接口不能仅凭一个 hash 证明这些条件真实成立。当前导入仅支持已核实计时字段的 Codex 纯文本会话；不能冒称已经支持 Claude 的对照实验。

## 5. 存储与轻量约束

单独的 `latency_impact_pairs` 表保存项目、实验、pair、基线、顺序、条件 hash 和两组原始计时。重复 pair 幂等，已有证据不可覆盖；同一原生轮次不可重复计入多个 pair；不同配置或基线不得塞入同一实验。页面仅展示最新实验，避免把异质实验混在一起。

每个项目最多保留最近 1000 对。自动清理后被淘汰的原生轮次不再拥有永久去重凭据；需要长期复核时由实验输出目录保留原始 manifest 和报告。对照表不存提示词原文、凭据或完整私密会话。

统计仅在管理页面读取指标时计算；写入发生在显式实验导入，不在检索或逐 token 路径。新增表和接口不引入模型、向量库或后台轮询。
