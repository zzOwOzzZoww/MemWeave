# 时间筛选与召回热路径优化

日期：2026-09-24。范围：知识管理页时间筛选与排序、召回词频统计、同机对照验证。

## 页面行为

- 待采纳、已采纳清单的“更新时间”表头均提供上箭头升序、下箭头降序，当前方向高亮；点击文字切换。两个清单共用排序方向，切换时回到第一页。
- 删除筛选栏中的“更新时间：最新／最早”下拉框。
- 日期框空白时在框内显示“起始时间／结束时间”，隐藏原生年月日提示；有值时显示所选日期。保留本机日期选择器及键盘操作，不增加前端框架或网络资源。
- 起止日期限制联动；按浏览器本地日期筛选，与列表显示的时区一致。刷新恢复空日期、最新优先、每页 20 条。

## 性能问题与实现

原来的 `anchor_terms()` 对查询里的每个词运行完整 `COUNT(*) MATCH`。中文二、三字切片可产生最多 64 个词；常见词的完整计数随命中记录数增加，即使最后该词因太常见而被排除，也先付出了完整计数成本。

最终实现是 `bounded_document_frequencies()`：

1. 用一条参数化 `WITH terms ... VALUES` SQL 批量查询词频。
2. 对每个词用原有 FTS5 `MATCH` 表达式，保留中文、大小写、标点复合词及短语语义。
3. 子查询最多读取阈值加一条。扩展阈值为 6 时，0～6 必须准确，7 及以上统一为 7，因为它们必定不参与扩展。
4. `_pin_discriminative()` 共用该函数，使用自己的原阈值。
5. 不引入缓存、外部服务、嵌入模型或持久词频表；读取当前索引，写入、删除和重建后立即生效。
6. 批量查询失败时退回逐词有界查询，保留原先逐词错误隔离。

没有关闭中文召回、词汇桥接、相关知识扩展；没有调低召回数量、改变原有相关性阈值或排名顺序。

试验过读取 `fts5vocab` 的方案，但本轮小库端到端改善不稳定，最终未采用。其试验报告保留在 `outputs/recall-frequency-20260924/report.json`。正式结果位于 `outputs/recall-frequency-20260924-bounded/`。

## 正式对照结果

同一台电脑、同一初始数据库副本，分别运行原完整计数与新有界批量计数。测试只调用本地代码，不调用模型；生产知识库只作为只读备份来源，测试写入发生在临时副本。

### 召回与结果一致性

| 数据 | 查询数 × 轮数／每种实现 | 返回 ID、顺序、来源、输出知识是否一致 |
|---|---:|---|
| 标准测试集 | 100 × 3 | 完全一致，0 个差异 |
| 本地知识快照查询 | 60 × 3 | 完全一致，0 个差异 |

标准集有 90 条正例和 10 条负例。两种实现 Recall@3、MRR@3 都为 1.0，负例错误注入率都为 0；固定以 3 为分母的 Precision@3 为 0.3333。不能因此声称真实场景准确率为 100%。本地快照查询无人工金标准，只能证明本次改动未改变结果，不能证明原结果全部相关。

| 测点 | 原实现 P50 / P95 | 新实现 P50 / P95 |
|---|---:|---:|
| 标准 100 条：纯检索 | 4.536 / 8.395 | 4.802 / 8.466 |
| 标准 100 条：Adapter | 17.898 / 28.296 | 19.162 / 28.566 |
| 本地快照 60 条：纯检索 | 5.837 / 9.628 | 5.887 / 9.762 |

结论：有界计数显著压低大量常见词命中时的词频统计成本；当前小库总体时延没有明显改善，部分测点略升，不能宣称整条链路提速 34 倍。压力测试的倍数只适用于词频统计。

### 真实 Runtime HTTP 与 Hook 子进程

使用独立 Runtime 和生产库的临时副本，实际启动两个 Hook 脚本。每个 Agent、每个入口、每种实现各 10 次。两种实现的返回知识、来源及输出状态一致。

| 测点 | 原实现 P50 / P95 ms | 新实现 P50 / P95 ms |
|---|---:|---:|
| Codex Runtime HTTP | 44.425 / 56.050 | 45.635 / 55.759 |
| Codex 完整 Hook 子进程 | 198.403 / 227.973 | 199.810 / 211.771 |
| Claude Code Runtime HTTP | 44.724 / 59.797 | 47.579 / 61.594 |
| Claude Code 完整 Hook 子进程 | 172.511 / 210.863 | 189.445 / 213.278 |

完整 Hook 包含 Python 进程启动、健康检查、HTTP 调用及审计，不包含模型首 token 时间。样本数小，仅用于确认当前入口可用和成本量级。截图中约 500 ms 是历史测量，本轮在当前代码和环境下未复现；不能把历史 500 ms 与当前约 200 ms 直接当作本次优化收益，也不能认定历史根因已经完全查明。
