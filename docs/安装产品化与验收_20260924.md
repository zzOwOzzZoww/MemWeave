# MemWeave 安装产品化与验收记录

日期：2026-09-24  
版本：0.5.0a1  
状态：本地实现、构建、隔离安装及本机升级完成；未发布到 PyPI / GitHub。

## 1. 用户流程

安装 → setup 配置 → 创建桌面快捷方式 → 打开管理页 → 选择接入 Agent → 正常使用原客户端。

pip 负责安装文件和依赖，setup 负责交互配置及当前用户桌面操作。首次在交互终端运行 memweave / memweave ui 时也会检查并进入配置。没有采用安装阶段执行交互代码的方式。

当前可在仓库目录执行：

```powershell
python -m pip install .
memweave setup
```

本地 wheel 已生成于 outputs/productization-20260924/wheel/。正式发布后的预发布命令预期为 python -m pip install --pre memweave-runtime，但目前尚未发布，不应让外部用户先执行该远程命令。

保留包名 memweave-runtime，命令名 memweave。PyPI 包名是否可用及账号归属仍需发布时确认。

## 2. 配置与凭据

新增 provider.py：保存 Base URL、模型名、API Key；模型兼容 Chat Completions。默认保留既有 DeepSeek 习惯，用户需要填写服务商实际提供的模型名，不保证 deepseek-flash 是任意服务商都支持的名称。

Windows 的 Key 用当前用户 DPAPI 加密。其他系统使用独立的权限 0600 文件，不能称为加密。API Key 不放入数据库、不显示在页面、不通过命令行参数传入。API 配置验证错误不回显请求输入。

更换服务商地址需要重新输入 Key。配置过的 provider.json 优先于遗留环境变量，避免桌面进程继承旧配置。未配置时仍兼容原来的环境变量。读取与解密凭据仅发生在学习模型调用及配置检查，不进入知识召回路径。

提供 memweave configure、doctor、doctor --check-api、shortcut。doctor 默认不请求模型；--check-api 明确发送短请求，有可能计费。管理页右上角“模型与工作区”提供同样的设置入口；保存不自动请求模型。

## 3. 安装组件与桌面入口

Hook 实现移入 agent_knowledge_bridge/hooks，图标移入包内 assets。旧 scripts 入口作为兼容包装保留。普通 wheel 安装无需访问源码 scripts 目录。

桌面入口使用安装环境的 pythonw.exe，后台运行管理页入口，避免终端闪退。启动失败给出提示并记录本地日志。快捷方式不包含 API Key 或 Runtime token；图标为用户提供的 MemWeave 图标。

Hook 启动器记录实际安装解释器及 MEMWEAVE_HOME。Windows 的 py.exe 仅负责引导到该解释器，避免虚拟环境安装后却从全局 Python 导入。

增加跨进程启动锁，避免连续双击启动多个 Runtime。Windows 虚拟环境可能产生启动代理进程，因此 Runtime 状态保存认证健康响应给出的实际 PID。重用服务前检查版本哈希与认证健康状态；停止时核对实际 PID。

## 4. 本次同时修复的逻辑

| 问题 | 本次处理 | 验收 |
| --- | --- | --- |
| 停用后仍召回 | 原生 Hook 只读启用状态；Adapter 和主要 Service 操作检查停用；学习写入前复核 | 停用后同轮重试不输出上下文，不调用学习模型 |
| 项目串库 | 按 cwd/Git 根生成稳定项目键；显式目录映射支持旧项目和有意共享 | 两工作区不同键，同仓库子目录一致；映射优先 |
| 归档被旧缓存绕过 | 返回历史 trace 前复核最新状态、范围和内容哈希 | 先召回再归档，同轮重试为空 |
| 使用反馈恢复归档 | used 只影响统计；最新 rejected 转隔离；恢复需显式审核/治理 | 归档 + used 仍归档；历史多次通过不能覆盖新反例 |
| 无关成功测试自动批准 | 普通模型提案保留 candidate，经验合约保留专用证据门 | 算术测试不能自动批准生产数据删除结论 |
| JSON Key 未脱敏 | 文本常见格式及结构化递归脱敏；外发模型再脱敏 | JSON、引号赋值、嵌套 token 均覆盖 |
| 学习失败被永久去重 | failed 最多尝试三次；运行租约超时可恢复；完成态去重 | 首次失败后第二次成功，第三次不重复模型请求 |
| Stop 阻塞模型调用 | 本地持久化队列，单后台工作线程，原生 Stop 只排队 | enqueue 不执行模型，后台完成；断开 Runtime 时任务保留 |
| 排队后读错下一轮 | 保存 transcript 字节边界，读取限定在原轮次边界 | 文件追加下一轮后仍学习第一轮 |
| 全量读 Hook 日志 | 仅读取末尾至多 256 KiB，再选最近 400 行 | 代码路径有界 |

队列最多 256 个待处理任务，保存最近 200 条终态任务。队列存本地路径和轮次边界，不复制原始会话。正在外发的请求无法因用户随后点击停用而撤回；停用后不继续落入新提案。

2. wheel 含两侧 Hook、HTML 和图标，不含数据库、输出目录或 .bak 文件。
3. 本地模拟 API 完成 setup/check；凭据不出现在输出。
4. 中文用户数据目录正常；测试桌面生成 .lnk。
5. Runtime 后台启动、认证健康、管理页加载；再次打开复用同一服务。
6. Claude / Codex 的实际 Hook 命令在隔离配置中安装并执行，各产生一次 recall_events。
7. 提交学习任务后后台完成，模型请求落在本地模拟服务。
8. 浏览器验证设置加载、保存、重新打开持久化、Key 留空、工作区选项、原五模块保持、1440/1100/1000 宽度不溢出，页面脚本错误 0。

该验收只调用本地模拟服务两次，没有调用付费模型。不是一次真实 Codex/Claude 客户端完整交互的重新验收，也不是模型效果或端到端首 Token 因果性能实验。

报告：install-report.json、settings-ui-report.json、final-report.json，均位于 outputs/productization-20260924。

测试中发现一项既有召回测试对等分记录的排序依赖时间，已调整合成夹具使目标锚点有明确排名差异，保留 origin 和 related_to 验证；没有为通过测试修改实际召回算法。
