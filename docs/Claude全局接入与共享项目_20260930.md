# Claude Code 全局接入与共享项目

Claude Code 的 MemWeave Hook 安装在当前用户的全局 `~/.claude/settings.json`，并不要求在 MemWeave 仓库启动客户端。此前 Hook 虽然全局触发，但任意启动目录都会生成不同项目键，导致启动器目录中的 Claude 无法读取共享项目下的 Codex 知识。

加入 Claude Code 时，安装器现在会在 `~/.memweave/config.json` 中将默认项目保存为 Claude 的共享项目。已存在的共享项目选择不会被覆盖，修改前保留配置备份：

```json
{
  "default_project": "claude-codex-mvp",
  "agent_projects": {
    "claude-code": "claude-codex-mvp"
  }
}
```

这会让同一用户的全局 Claude 会话从启动器、普通目录或未单独映射的仓库读写同一共享池。知识可以来自 Codex，也可以来自 Claude；来源 Agent 不决定是否能读取。召回与 Stop 后台学习采用同一项目选择规则。

后续通用修复已将此行为扩展到所有 Agent。优先级是：`MW_PROJECT_KEY` / `AKB_PROJECT_KEY` 显式环境变量 → `workspace_projects` 中最长匹配路径 → `agent_projects` 中对应 Agent 的共享项目 → `default_project` → Runtime 状态或默认项目。只有未指定 Agent 的工作区身份查询保留自动工作区 hash。Claude、Codex 和 Runtime API 客户端都不再默认按启动目录拆分知识池。

全局接入不等于搜索整个数据库。项目范围、candidate/active 准入、证据、版本、相关性、预算和 Agent 停用门禁均保留。`scope=user` 的知识仍按既有机制跨项目可用。

需要独立隔离的目录，应在 `workspace_projects` 中明确绑定其他项目。开启共享模式会同时改变该 Agent 在未映射目录中的学习归属，不适合把本来需要隔离的多个客户项目无区分地接入。

已安装用户重新加入 Agent 或点击“修复接入”会补齐配置，清理所有事件组内的重复或受限 MemWeave Hook，同时保留其他工具的 Hook。安装器和检查器均支持 `CLAUDE_CONFIG_DIR` / `CODEX_HOME`；全局范围是当前用户当前选中的客户端配置，不会遍历其他操作系统账户或未知配置目录。已有全局 Hook 每次启动子进程读取共享池配置，无需重启客户端即可读取新池配置；客户端可能缓存 Hook 设置，因此修改 Hook 后建议重启客户端。旧的空召回记录不会改写为成功。

目前只有 Claude Code 和 Codex 提供维护中的原生自动 Hook。其他 Agent 的登记会配置同样的全局共享池，但仍需客户端 Adapter 主动使用 Runtime API。Python `MemWeaveRuntimeClient` 可省略 `project_key` 使用默认共享池；显式传入项目或工作区映射仍可隔离。登记不等于完成该客户端的自动上下文注入。
