# 知识版本与冲突治理：实现和验收（2026-09-26）

## 要解决的问题

同一项目或同一用户偏好的新旧说法可能不同。只按关键词检索时，两条已采纳知识都可能进入上下文；即使把旧条归档，LFHV 后续也可能将其恢复。这会让跨 Agent 共享的内容相互矛盾。

本轮把能可靠解析的**单句、无条件赋值**建成 `scope + project_key + topic -> value`。例如“审核期限正式定为24小时”和“审核期限正式定为48小时”属于同一事项的不同值；“1天”和“24小时”被规范为相同值。`user` 作用域跨项目对齐，`project` 作用域只在相同项目对齐。两种作用域不会静默互相覆盖。

## 生命周期

1. 写入时提取事项和值，记录原文指纹。没有足够把握时不提取，继续走原有候选审批流程。
2. 新候选与已采纳或曾经采纳、尚未被替代的旧值冲突时，管理页展示旧知识的标题、正文和来源。普通批准及批量批准不能绕过冲突。
3. 人工核对后选择“采纳并替代旧版”。请求带上当前冲突知识的完整 ID 集合。事务内重新核对集合、原文指纹，归档旧版并激活新版；过时的页面选择会失败。
4. 保存旧版正文、`superseded_by` 与有效期终止时间。普通问题仅检索当前版本；明确问历史时可读旧版，并附上历史提示。后续版本被永久移除也不会自动恢复旧版。
5. 检索和上下文发出前检查版本状态。旧轮次缓存、直接生命周期流转和 LFHV 影子恢复不能将已替代版本带回当前上下文。管理页可召回数字与实际版本检查一致。

`valid_from` 和 `valid_until` 是本地批准/替代发生的时间，不解析自然语言中的未来生效时间。迁移前旧知识的实际生效起点未知，保持空值。

## 组件与数据

| 组件 | 责任 |
| --- | --- |
| `knowledge_versions.py` | 保守提取、单位归一、作用域槽、冲突集合、写时标志和迁移 |
| `store.py` | 写入索引、审批事务、历史检索、状态检查、管理统计、永久移除墓碑 |
| `decisions.py` / `reuse.py` | 查询过滤、真实发出前复核、轮次缓存失效、历史标签 |
| `governance.py` | LFHV 不把替代旧版计为误归档或复活目标 |
| `contracts.py` / `service.py` / `daemon.py` | `supersedes` 明确传入及422错误返回 |
| `knowledge_dashboard.html` | 冲突详情、独立替代按钮、已替代记录只读 |

SQLite 新增 `claim_topic`、`claim_value`、`claim_fingerprint`、`claim_conflicted`、`superseded_by`、`valid_from`、`valid_until`。迁移在写锁下回填，幂等；不会覆写真实正文。查询时只读索引和已有状态，不新增模型调用，也不做全库冲突扫描。

## 本轮验收

- `pytest`：最终 **380项测试和9项subtests通过**（本轮新增30项版本测试）。覆盖并发审批、旧库迁移、两侧真实Adapter、项目隔离、过期选择、缓存、直接恢复、删除新版、原文被外部修改等。最终日志在 `outputs/knowledge-versions-20260926/pytest-final.txt`。
- 版本评测：10个事项 × 两种作用域 × 两个目标Agent = **40组生命周期、200次合成召回观察，全部符合预期**。这是模板组合，不代表40类独立任务；不调用模型。逐例见 `outputs/knowledge-versions-20260926/lifecycles-final/`。
- 旧回归：原扩展矩阵本地200次符合预期，40个需真实模型提取的观察标记 `not_run`；混合库40次符合 required/forbidden。见同目录 `extended-final/`、`mixed-final/`。
- 规模：1115条合成知识（含1000干扰），100题×3轮，正例270/270命中、负例30/30无注入。Adapter P50/P95=49.895/70.413ms，上一轮45.329/59.415ms；检索P50/P95=16.988/33.628ms，上一轮15.084/27.690ms。两次是顺序运行，不能作严格因果性能结论；不含客户端Hook、模型推理或TTFT。见 `performance-final/report.json`。
- 浏览器：隔离Runtime+临时SQLite，检查批量冲突保留勾选、冲突正文、取消、明确替代、详情滚动重置、旧版只读，无JS异常；截图和报告在 `ui-release-2/`。原有批量审批/移除管理页验收也通过。未对用户正式数据库执行替代动作。
- 正式库：升级前使用SQLite backup API备份为 `data/backups/before-knowledge-versions-20260926-180746.db`（137条，`quick_check=ok`）。新版Runtime已在 `http://127.0.0.1:8765/knowledge` 启动，认证健康检查和运行源码版本匹配；迁移后`quick_check=ok`，记录仍为137条。既有真实库中符合本轮窄语法的记录为0，因此没有现存知识被标记版本冲突。本轮的真实用户收益仍待后续使用验证。

## 边界与下一步

当前识别器只覆盖简单赋值，无法可靠理解任意同义“候选时限/审核期限”、复合条件、多值配置或未来生效时间。无法对齐的知识仍需人工判断；不宣称全库语义冲突已解决。历史知识保留是可追溯性设计，尚不代表整个SQLite字节长期有界。

下一轮应采集**真实的冲突标注集**，分别测冲突检出率、误判率、审核节省时间和错误注入率；再做同机交错的框架开关对照，记录实际Hook增加的首字耗时。现有合成测试不能证明任务收益或“越用越聪明”。
