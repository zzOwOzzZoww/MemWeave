# MemWeave v0.2 证据生命周期验收记录

## 本次目标

将 v0.1 的“发布即生效”改为带证据门的生命周期：

```text
candidate → verified → active
          → rejected → quarantined
```

普通检索只返回 `active`。候选和隔离知识只能通过 `knowledge_review_queue` 查看。

## 已实现

- `knowledge_publish` 创建 `candidate`，不会立即污染正常召回。
- 新增 `knowledge_review_queue`，支持查看 `candidate`、`quarantined` 或全部审核项。
- `verified/rejected` 强制要求客观 `evidence_kind` 和非空 `evidence_ref`。
- 验证数大于拒绝数时进入 `active`。
- 拒绝数大于等于验证数且存在拒绝时进入 `quarantined`。
- 隔离知识在后续验证重新占优时恢复为 `active`。
- 返回 `confidence = verified / (verified + rejected)`。
- Evidence 保存状态变更前后值，能够回看每次晋升和降级。
- v0.1 SQLite 数据库启动时自动补齐新列；已有验证票的 `active` 记录保持生效，没有验证票的旧 `active` 记录降为 `candidate`，防止绕过新证据门。

## 当前边界

证据门目前能强制“验证类型和引用必须存在”，但还不能自动确认引用内容真实。下一步应实现验证 Adapter，由框架直接运行测试或读取结构化结果，而不是只接受 Agent 对测试结果的文字声明。
