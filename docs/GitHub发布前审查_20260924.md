# MemWeave GitHub 发布前审查

日期：2026-09-24。范围：当前本地代码、打包配置、主要学习与治理路径。仅审查和隔离复现，没有修改产品代码，没有上传 GitHub，没有请求付费模型，没有删除真实知识。

## 结论

项目有足够内容作为个人项目的公开 Alpha：跨 Agent 接入、共享知识、候选审核、生命周期治理、可观测复用、四阶段检索和管理页已经形成可运行的整体。

目前不适合标记为稳定版或宣传“安装即用、完全隔离、越用越聪明已被证明”。建议先修复下面的发布门槛问题，再开放 Alpha 试用。无需为了发布继续增加大型检索依赖或重做页面。

上一轮完整测试为 295 passed、9 subtests passed；这不能覆盖本轮新增的负向场景。本轮按场景单独复现，证据保存在 `outputs/release-audit-20260924/`（该目录被忽略，不作为公共发布内容）。

## 必须先处理

### 1. 停用未阻断实际召回和学习入口

证据：`store.py:1949` 只更新 registry 的 enabled；`service.py:90` 仅转发。`daemon.py` 的学习入口和 Adapter 没有把注册状态作为运行门槛。

隔离复现：登记 Codex 后停用，`POST /v1/learning/recall` 返回 200，仍输出已有知识上下文。仅变更 UI 颜色不足以实现用户理解的停用。

修复方向：在实际 recall/learn 的入口统一检查显式停用，并覆盖 Runtime 和本地降级路径；明确未登记 Agent 的策略。已经安装的 Hook 可以保留但必须立即空返回；停用后的后台任务也应重新检查状态。提供卸载 Hook 的明确入口，避免误删其他插件配置。

验收：停用后不能输出上下文、不能新建学习记录或调用提炼模型；重新启用后恢复。直接 API、本地 fallback、已缓存的轮次均覆盖。

### 2. 全局 Hook 的项目键不随工作区变化

证据：两个 Hook 的 `selected_project()` 均调用 `runtime_state.project_key()`；后者只读环境变量、Runtime 状态或固定默认值，不接受 cwd。Adapter 收到 cwd 后仍使用构造时的 project_key。

隔离复现：Alpha 工作区的项目知识在相同全局默认项目下，被 cwd 指向另一个 Beta 工作区的请求召回。数据库显式传不同 project_key 的隔离并不能保证全局自动接入时的隔离。

修复方向：增加工作区／仓库根目录到项目键的明确映射，支持用户主动指定多个工作区属于同一项目；用户级知识跨项目共享，项目级知识按映射限定。解析失败不要自动归到所有工作共用的项目。

验收：不同工作区默认隔离，同一项目的两种 Agent 共享；用户级知识继续共享；映射修改不会把旧数据隐式重新归属。

### 3. 生命周期存在绕过与缓存失效遗漏

证据：`claude_learning_adapter.py:193` 遇到已有轮次直接返回 context_text，不复核条目的当前状态；`store.py:2172` 根据累计 verified/rejected 数重新计算状态。

隔离复现：

- 先召回再归档，同一 session/turn 重试仍输出旧缓存上下文。
- 已归档且以前验证通过的知识，收到普通 `used` 反馈后变为 active。
- 两次验证通过后收到一次 rejected，状态仍为 active。

问题在于“本次被使用”不是“重新授权”，历史票数也不能自动覆盖人工拒绝或新反例。最近完成的永久删除会清理上下文缓存，但归档、隔离路径尚未统一处理。

修复方向：建立显式状态转移表；used 仅增加使用统计；归档复活只走明确治理／审核操作；新反例或人工拒绝应有明确优先级；所有影响可召回性的变更一致地处理缓存。返回缓存时验证状态和版本。

验收：active→archived/quarantined 后，新轮次及同轮重试均不可召回；延迟到达的 used 不能复活；恢复操作可追溯。

### 4. 自动批准验证了事件成功，尚未验证事件支持该知识

证据：`claude_learning_adapter.py:502` 普通知识只要引用本轮某个成功 test/command，就会记录 verified。经验合约有更严格的适用条件／命令匹配，但普通知识路径没有等价约束。

隔离复现：用假的 reviewer 返回“生产数据一小时后必须删除”的用户级知识，引用真实存在于测试夹具中的算术测试通过事件，最终 promoted=1。没有外部模型调用；这模拟的是模型引用了不相干证据。

修复方向：无确定性支持关系的结论停留 candidate；精确约束可用产物验证器关联“该字段／命令／结论”，不以任何一条测试成功作为通行证。scope=user 的自动扩散要更谨慎。仅增加第二次 LLM 判断不能变成客观证明。

验收：无关测试成功、同轮多个主题、先通过后失败、来源摘录带指令等场景不能把错误结论推成 active。

### 5. 敏感信息过滤有真实缺口，公开目录也需清理

证据：`claude_transcript.py:13` 的规则匹配键名后直接出现冒号，未覆盖 JSON 中键名结束引号。`review_text()` 包含用户请求、回答、工具摘要；自动学习会将其发送给配置的 reviewer。因此“SQLite 本地存储”不等于“全部处理不出本机”。

隔离复现：`{"api_key":"DEMO_ONLY_NOT_A_REAL_SECRET_123456"}` 的模拟值没有被 redact_text 移除。本轮不输出或扫描真实密钥值。

修复方向：对结构化工具输入按敏感字段名递归处理，并覆盖 JSON、环境变量、URL、Header 等典型形式；发布／提炼／日志路径共用入口。明确公开说明远程提炼的数据范围与关闭方式。规则脱敏不能宣传为完全防泄漏。

发布目录检查：data/ 和 outputs/ 已排除；但 `.workbuddy/memory` 有本地记忆文件，根目录有 35 张页面截图，现有 `.gitignore` 未覆盖这些路径。README、部分脚本与文档也含个人绝对路径。截图可能带真实知识和工作路径，应使用合成演示数据重新制作，不要直接提交当前工作目录。

验收：合成敏感字段不会进入 reviewer 请求和持久化事件；按发布白名单导出并人工复核；加入 secret scan。当前审查不等于完整安全审计，未发现或未检查的风险不据此排除。

### 6. 普通安装包无法完成 Hook 接入

证据：`pyproject.toml` 只收集 src 包与 HTML；Hook 在仓库顶层 scripts。`agent_registry.py:286` 通过文件父目录定位 scripts。

隔离复现：从复制的干净源码构建 wheel 成功，检查包内容未包含两种 Hook 脚本。解包后使用隔离解释器，只从新包导入；`memweave init` 成功，但 `install_native_hook('claude-code')` 报 `MemWeave hook script not found`，没有修改用户真实 Agent 配置。

修复方向：把可执行 Hook 放进可发布包中，优先提供模块／console entry point；避免根据 src 的层级假设安装位置。非 editable 安装需在空目录验收，不能只测开发树。

验收：普通 wheel 安装→init→ui→接入→召回→学习→停用／卸载完整通过。明确首发测试过的操作系统与 Agent 版本。

### 7. 学习失败后的同轮重试被去重挡住

证据：`learning.py:119` begin_run 对唯一 turn_hash 冲突统一返回 None；Adapter 直接解释为 duplicate_turn，没有区分上次 completed、failed 或崩溃遗留的 running。

隔离复现：reviewer 第一次抛临时错误，第二次准备正常返回；重试却返回 duplicate_turn，reviewer 总调用次数仍为 1。

修复方向：只有 completed 可以直接命中完成态去重；failed 允许有次数上限的重试；running 使用租约和过期接管。部分成功需保证提案和关联写入幂等，防止重试重复增证据。

验收：网络错误后可重试、进程中断后可恢复、重复 Stop 不重复提炼已完成轮次、部分提案成功后重试不重复计数。

## 可作为 Alpha 限制，但要明确披露

### 8. 热路径故障预算和结束阶段同步等待

`MemWeaveRuntimeClient` 默认 timeout=120 秒，Codex 路径未为 recall 单独缩短；Claude runtime client 当前采用 20 秒。健康检查成功后不意味着下一次请求不会卡住。安装生成的 Hook 是同步的；learn 在 reviewer 返回之前不会结束，默认 reviewer timeout 为 90 秒。隔离事件栅栏复现确认 learn 等待 reviewer。

应设置召回专用的短超时和快速降级，学习交给有界后台队列，区分提交成功和实际完成。真实首 token 开关对照仍是零合格配对，不能把本地检索 P95 当成用户额外等待。

### 9. 活动知识受控，不等于整个库体积有界

知识有归档和删除，但 agent_events、learning_runs、recall_events、reuse_traces 及 Hook JSONL 仍随使用持续增加；agent_events 还有禁止删除触发器。目前没有统一审计保留期限／体积预算。Agent 状态检测中 `read_text().splitlines()[-400:]` 会先读整个日志再取最后 400 行。

管理页最多取 2000 条后前端分页，长期大库的分页、统计和筛选完整性需要重新核验。优先加事件保留、压缩、日志轮转和有界尾读，再谈“整个知识库不会无限膨胀”。

### 10. 发布说明与评测边界

未见 LICENSE 文件和 `.github/workflows`；README 仍包含个人路径、旧 Demo 入口，以及与现实现不完全一致的边界描述。README 指向 outputs/ 的实验报告，但 outputs/ 已忽略，外部使用者无法看到对应证据。

发布时需要选择明确许可证、梳理第三方代码来源、提供合成数据 Demo、干净安装 CI、基础故障用例与匿名评测摘要。已完成的合成任务实验只能支持其任务分布，不能直接推出开放任务准确率或长期越用越聪明。

本轮还检查了现有证据保留、FTS 缓存和 Runtime 启动代码；并未穷尽并发、提示注入、所有操作系统和所有 Agent 版本。

## 建议发布顺序

1. 先解决停用门槛、工作区隔离、生命周期与证据晋升、脱敏这些控制问题。
2. 修复普通安装包与学习重试，加入各自失败回归。
3. 对外包只包含代码、合成用例和脱敏文档；提供真实安装演示及已知限制。
4. 先发 Alpha，小范围用户反馈；随后进行真实跨 Agent 使用评测、长时间存储增长实验和 TTFT 开关对照。

不需要为了开源把所有研究问题解决，但用户点击的停用、归档、隔离和安装说明必须与实际行为一致。
