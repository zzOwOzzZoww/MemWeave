# MemWeave 轻量化实测报告

> 2026-09-22 · 由 `scripts/report_footprint.py` 实测生成，可随时复跑
> 测点：系统临时目录（**不要在同步盘/杀软扫描路径上测**，见评审文档 §4.5）

## 0. 结论先行

**显存占用 = 0。这不是"优化过的结果"，是架构事实。** 源码里 `torch / transformers /
sentence-transformers / numpy / faiss / onnx / tokenizers` **引用数为 0**：MemWeave
不跑本地模型、不做 embedding，检索用 SQLite FTS5，推理走用户自己的模型 API。
**没有张量就没有显存。**

真正要回答的是"内存和依赖有多重"。实测结论：

| 层 | 额外内存 | 第三方包 | 启动 |
|---|---|---|---|
| 核心（store + governance） | **+4.9 MB** | **0** | 39 ms |
| service facade | +4.9 MB | **0** | 37 ms |
| 学习 hook（进程内） | **+9.4 MB** | **0** | 96 ms |
| HTTP daemon | +33.3 MB | **15** | 484 ms |

**重量全部集中在 HTTP daemon 那一层，而它是可选的。** 不开 daemon，整套东西
**零依赖 + 不到 10 MB**。

## 1. 实测数据

### 1.1 运行时足迹

| layer | init | peak RSS | added | third-party packages |
|---|---|---|---|---|
| python + stdlib | 0.0 ms | 19.2 MB | +0.0 MB | 0 |
| core (store + governance) | 39.2 ms | 24.2 MB | +5.0 MB | 0 |
| service facade | 36.8 ms | 24.2 MB | +4.9 MB | 0 |
| learning hook (in-process) | 95.5 ms | 28.9 MB | +9.4 MB | 0 |
| HTTP daemon | 483.6 ms | 52.8 MB | +33.3 MB | 15 |

> RSS 在全新解释器里测量，含 Python 本体；要比较的是 **added** 列，不是绝对值。

### 1.2 存储增长

| 记录数 | 库大小 | 字节/记录 |
|---|---|---|
| 200 | 372 KB | 1905 |
| 1000 | 1408 KB | 1442 |
| 5000 | 6608 KB | **1353** |

收敛到 **≈1.35 KB/记录**（正文 + FTS 索引 + 证据行）：

| 库规模 | 磁盘 |
|---|---|
| 1 万条 | ≈13 MB |
| 10 万条 | ≈135 MB |

SQLite 不会把库读进内存，所以**万条级知识库的内存占用与空库几乎无差别**。

### 1.3 daemon 层的依赖体积

15 个包共 15.2 MB 磁盘，其中 pydantic 家族独占 9 MB：

`pydantic_core 5.54 / pydantic 3.45 / anyio 1.74 / fastapi 1.20 / click 0.85 /
watchfiles 0.71 / starlette 0.57 / uvicorn 0.48 / orjson 0.22 / 其余 6 个共 0.5`（单位 MB）

**为了提供几个 HTTP 端点，代价是 33 MB 内存 + 15 个包 + 10 倍启动时间。**

## 2. 本轮做的四件事

### 2.1 依赖分层：核心从 3 个依赖降到 0

`pyproject.toml` 原本把 `fastapi / pydantic / uvicorn` 列为**必装依赖**——但核心代码
（`store / governance / reuse / learning / service / *_transcript`）从头到尾只用标准库。

改法：`dependencies = []`，web 栈移入 `[runtime]` extra，另给 `[all]` 一键装。

```bash
pip install .                 # 核心：零依赖
pip install '.[runtime]'      # 加 HTTP daemon
```

同时 daemon 缺依赖时给出**可执行的安装提示**，而不是抛 `ModuleNotFoundError`：

```
the MemWeave HTTP daemon needs the optional 'runtime' extra (missing: fastapi).
  pip install 'memweave-runtime[runtime]'
The hooks and the core need no dependencies at all.
```

### 2.2 治理账本从 O(查询数) 收敛到 O(已归档记录数)

**这是本轮查出来的真问题**，而且很讽刺：一个专治"只进不出"的治理层，
自己的账本在无界增长。

原实现每探一次写一行 `shadow_hits`。实测：100 条已归档记录 + 50 次探针 →
**2000 行 / +588 KB**，账本涨得比它治理的知识库还快。

改法：改为**按记录聚合**（`hit_count / best_rank / first_seen_at / last_seen_at`）
用 UPSERT 累加；`resurrect()` 复活时清掉该记录的行。实测：

| 指标 | 值 |
|---|---|
| 已归档记录 | 20 |
| 探针次数 | 500 |
| **实际账本行数** | **8** |
| 若按次存则需 | 4000 |
| 单行最大计数 | 500 |

**账本大小现在由淘汰策略决定，不再由查询量决定**，上界 = 当前已归档记录数。

### 2.3 生命周期审计表加上限

`lifecycle_audit` 每条转移写一行；记录若在 active↔archived 间来回震荡，同样无界。
加入 `AUDIT_ROWS_PER_RECORD = 50` 上限，只裁旧记账行，**记录本身永不触碰**。

### 2.4 把"轻量"变成会失败的断言

新增 `tests/test_footprint.py`（6 项）。**"轻量"是会静默衰减的性质**：某天有人图方便
在核心 import 一个 web 框架，或给每条请求 append 一行审计，它就没有了。

| 测试 | 守的是什么 |
|---|---|
| 核心源码不得出现 fastapi/pydantic/uvicorn/starlette/mcp | 依赖不会悄悄爬回来 |
| **干净解释器里 import 核心，加载的第三方包必须为 0** | 不看源码怎么写，看实际加载了什么 |
| 字节/记录 < 6 KiB（300 条实测） | 加列/加索引/加 blob 会立刻失败 |
| 100 次探针 / 3 条已归档 → 账本行数 ≤ 3 且 < 100 | **账本不能比库涨得快** |
| `resurrect` 后账本行清零 | 账本只描述"当前被淘汰的" |
| 震荡 60 次 → 审计行数 == 上限 | 记账不会无界 |

## 4. 给使用者的推荐装法

```bash
# 只想让 agent 有记忆：零依赖、约 10 MB、不需要常驻进程
pip install .
export MW_RUNTIME_MODE=local     # hook 直接在进程内跑

# 需要多 agent 共用 + dashboard：再加一个 extra
pip install '.[runtime]'
```

**默认路径不碰 web 栈**——这是"别人愿意用"的关键：安装前不需要先接受一整套框架。

## 5. 复跑方式

```bash
PYTHONUTF8=1 PYTHONPATH=src python scripts/report_footprint.py
```

数字会随机器波动（尤其 init 与 RSS），但**量级与依赖计数是稳的**；
`tests/test_footprint.py` 里那些断言才是需要长期守住的部分。
