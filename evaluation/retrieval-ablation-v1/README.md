# DBSA / LFHV 检索层消融

## 冻结协议

目的：在同一份输入、标签和预算下，测量移除一个组件后的条件贡献，不新增召回能力。

首次结果见 [RESULTS.md](RESULTS.md)，机器可读摘要见 [results-20260930.json](results-20260930.json)。报告保留了一个近似问题误召回，不是所有诊断案例全绿。

五个实验臂：完整系统、关闭 Bridge、关闭 Sibling、关闭 Anchor、关闭 LFHV。其他证据、范围、版本、仲裁与回答充分性检查保持开启。

- 回归集：`evaluation/memweave-cross-agent-v1/cases.jsonl` 的 300 条 test 案例。这个集合此前参与过修复，不是独立留出集。
- 诊断集：本目录 12 条手工构造案例，覆盖词汇桥接、同主题补全、稀有词补页、归档恢复，以及跨项目、已替代、隔离、近似但不相关的负例。部分形状来自已有回归测试，不代表自然请求分布。
- 所有实验臂固定使用 `on-demand-v2` 标签。关闭 LFHV 后应恢复的知识仍然计为应召回，不能改标签让关闭臂也得满分。
- 每条案例先建立独立临时数据库，再通过 SQLite backup 为每个实验臂、每次重复创建相同快照。用户范围记录、命中计数与恢复状态不会串到其他案例或实验臂。
- 默认基础召回 limit=3、Anchor slack=2、上下文字符预算=4000。所有臂使用相同上限；实际输出量可以不同。
- 每个臂使用新的查询统计缓存；以固定种子打乱执行顺序，默认重复三次。逐次检查证据别名、输出顺序、恢复结果及上下文体积是否完全一致。
- 不调用模型、不调用外部服务、不读取个人记忆数据库。

## 运行

```powershell
python scripts/evaluate_retrieval_ablation.py --output outputs/retrieval-ablation-20260930 --repeats 3
```

输出目录必须不存在，防止覆盖历史结果。可用 `--suite diagnostic` 做小规模脚本验收。

产物：`report.json`、`REPORT.md`、`predictions.jsonl`。报告记录源码与数据 SHA256、Python/SQLite/操作系统版本、逐组件触发覆盖、分类成绩、配对变化和重复一致性。

## 指标和边界

正向证据召回率是每条正例的必需证据召回率再取平均。完整且干净率要求所有必需证据均出现，且不输出 allowed_ids 之外的记录；诊断案例中辅助映射可以明确标为允许输出，但不代替必需证据。禁止注入率只统计 forbidden_ids，不能代替完整的错误注入指标。上下文体积统计实际输出全文 UTF-8 字节，不换算成 Token。

P95 测量 adapter.recall 的本地调用，包括检索、复用与恢复事务写入，不包括夹具建立、快照复制、Adapter 初始化或真实 Hook 传输；它不是 LoCoMo 搜索层 P95，也不是 TTFT。

移除一个阶段可能改变后续阶段的种子和空位。特别是关闭 DBSA 某阶段可能给 LFHV 留出更多空位，Anchor 也可能重新找到某些候选。消融贡献有相互作用，不能相加。相同成绩需要结合阶段触发覆盖解释，不能直接认定组件没有价值。

诊断集的成功只说明所构造机制场景有效；回归集的成功只说明已有案例保持通过。这里不评估最终回答、真实任务成功率、长期线上收益或统计显著性，不据此声称参数最优或开放领域 100% 召回。
