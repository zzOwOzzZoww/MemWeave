# 独立断言修复复测：v2 内容覆盖口径

本协议在当前实现、用例和说明完成后冻结再运行，不覆盖 v1 的旧结果。被测对象是混合原文准入的 Core 修复，不是公开问答任务成绩。

## 保持不变

- 使用 v1 同 revision、同 SHA-256 的 LongMemEval cleaned S 全部 500 题，不挑题。
- 用户消息仍整条构造一个候选，固定类型判断、统一 durable、最多 8,000 字符、每题独立临时数据库，与 v1 相同。
- 提取器和产品代码不能读取问题、答案、has_answer 或原始证据 ID；只在最终评分阶段使用公开证据标注。
- 不调用模型，不人工批准，不读取生产知识库；运行期间不改实现或数据。

## 产品行为变化

当用户原文候选仅因临时性/不确定性被拒，Core 可从该候选已引用的原文中保守选取最多三段独立、完整、最长 600 字符的陈述。

每段必须再次用原始来源补全其限定上下文。敏感内容、禁止保存、模型标为 temporary/uncertain、引用代码、疑问、计划和不完整片段不能通过该路径洗成事实。选出的记录只做 candidate、project，不继承整轮授权；丢弃内容的标题与检索词不能继续留在记录中。此机制不是通用真值判断器。

## 新增可核验指标

v1 的消息 outcome 保留，但 v2 额外核查实际存储正文与来源的字面对应，逐条记录 `retention_coverage=full|partial|none`、原始输入文本中的字符偏移及保留字符数；完整覆盖仅忽略输入首尾空白，偏移不先裁剪原文。不输出新的私有记录或内部标识。

官方 has_answer 标记的是整条消息，不是原文里的具体答案跨度，因此必须分别报告：

1. 整条原文保留的标注消息数；这个是严格字面覆盖，不是问答准确率。
2. 仅部分原文保留的标注消息数；只能叫“标注消息有片段保留”，不能叫“官方证据恢复”。
3. 无保留、超长未接入、active 及实际唯一记录数。

消息总分母仍为全部用户消息，官方用户标注分母仍为 832。不能把挑出一句不相关的内容当整条证据都保住。对 partial 标注消息保留偏移供复核，不用标准答案在准入侧挑片段。

没有独立治理动作/断言真值标签，不报告自动批准精度、正确过滤率、人工节省比例或统计显著性。这份数据已经用于诊断和指导修复，不能当作盲测或泛化证明。
